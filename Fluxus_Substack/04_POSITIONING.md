## 三、你的硬旗舰:**筛选 + 一个数字**

### 先把我加多的东西砍掉

你说「four hard goods 听起来好多」—— 对。我在累加,不是在聚焦。**每个产品只留一件硬货:**

| 产品 | **唯一硬货** |
|---|---|
| **How Much**(Substack) | **我的筛选,结论落在一个仓位数字上** |

| **Masterclass** | **怎么把这套筛选练成手感** |

**三件商品,三件硬货,不再加。**

### 旗舰的产品定义

**别人给你名字。我给你名字后面那个数字。**

榜上十家 + TSF + JB,**全部停在「买什么」**。没有一家把判断转成仓位。
你 Voice Bible 已经查证过:**Finance 付费 Top 50 里没有任何一家对 position size 做承诺。**

```
TSF   :  55 张图  →  一句 Bottomline  →  ❌ 停在这
JB    :  150 条流 →  5 个想法        →  ❌ 停在这
你    :  少量图    →  2–3 个名字      →  ✅ 每个后面一个仓位数字 + 失效条件
```

**你的筛选层和他们不同的地方,不是数据源,是筛完之后还多走一步。**

### 每期骨架(比 TSF 简单得多,这是特性)

```
① 上期对账        一段话。对的错的都说。← 是格式,不是"第四件硬货"
② 现在什么环境    3–5 张图,不是 55。regime 是入口,不是主菜
③ 筛出来的名字    2–3 个。为什么是它们,为什么不是别的
④ 每个名字一个数字 仓位 % + 止损 + 失效条件   ← 全刊唯一不可替代的一节
⑤ 持仓表          按仓位排序
```

> **别去和 TSF 比图多。** 他一期 55 张,你比不过也不该比 —— 那是转发商的活。
> **8–15 张图,2–3 个名字,每个带数字。** 少而硬。这同时满足你的「少发精发」和「反多巴胺」。

### 为什么这个筛选别人抄不走

不是因为数据,是因为**筛选规则本身要用真钱验证过**:

```
regime 决定风险预算   ←  breadth/GEX(公开原料)
主题龙头三档          ←  你的三原型 → 三档仓位
形态紧不紧            ←  no tightness, no trade
两腿结构              ←  战术腿大而紧 / 核心腿小而宽
0.25% R · 1/75 Kelly ←  上限 3%,单主题 1.5%,回撤自动刹车
```

**这五层里,前两层是公开的,后三层是你的,而且有 331 笔成交做背书。**
TSF 和 JB 都没有第三到第五层 —— **他们不给数字。**

## 三·五、旧版「全量对账」的降级说明

上一版我把「对账」写成核心护城河。**降级成格式装置。**
它确实榜上无人做、确实值钱,但它是**信任装置**,不是**产品**。产品是筛选和数字;对账是让人相信那个数字的东西。

一段话就够,不需要专门的栏目和台账系统。

你的刊已经叫 **How Much** 了。名字是对的,产品要配上。

### 每期的固定骨架

```
① 对账(开篇)   上一期说的那几个,现在怎么样了。对的错的都列。
                 ← 这是全刊最硬的一块,榜上无人做
② 现在的判断    敢表态。一句结论,不是"可能涨也可能跌"
③ 仓位          这个判断值多少风险预算。数字,不是形容词
④ 失效条件      什么发生了我就认错。事前写死,写具体
⑤ 持仓表        按仓位大小排序(抄 TSF/JB 的 open book)
```

**为什么这个是硬的,而 Weather Report 是软的:**

| | Weather Report | **带仓位的决策 + 对账** |
|---|---|---|
| 别人能做吗 | **能,人人都有 breadth** | **不能** —— 需要 7 年真实记录 + 公开对账的胆量 |
| 数据从哪来 | 公开指标 | **你自己的成交记录** |
| 复制成本 | 一周 | **七年** |
| 会被打脸吗 | 不会(也没人在意) | 会,**而这正是它值钱的原因** |

> 你的 `performance_review.py` + trade log + R 分布 **已经能自动生成对账**。
> 别人做不了这件事不是因为技术难,**是因为他们不敢,或者根本没有干净的记录。**

### 一句话产品定义

> **别人告诉你买什么。我告诉你买多少 —— 并且下一期告诉你上次那个多少是对是错。**

**观点(strong opinion)+ 仓位(可量化)+ 失效条件(loosely held)+ 对账(不可伪造)。**
这四件套里,前三件别人可以模仿,**第四件需要七年的干净记录做抵押。**

### Weather Report 降级

不删,**降成旗舰里的一节**(②的输入),或者每月一篇免费引流。
**它是原料,不是产品。**

## 四、Discord 的硬货是什么

你问的是对的问题:**两边都必须有硬货,否则贵的那个卖不动。**

### 一件事,不是四件

```
Substack  =  我的筛选和结论(想清楚了才写)
Discord   =  我实际在做的(正在发生)
```

**Discord 唯一的硬货:实时成交播报 —— 入场、加减、离场,带 size 和 stop。**

平台访问、盘中 levels、问答**都不是硬货,是附赠**。它们不该被当成卖点写进权益页的第一行:
- **盘中 GEX 不独有** —— MenthorQ、SpotGamma 都在卖,TSF 直接转发 MenthorQ 的图
- **平台是附加值**,不是购买理由(而且它归 Substack 付费档)
- **问答是社群的自然属性**,不是产品

**为什么「实时成交」是真硬货:** 它是唯一**结构上不可能被信件交付**的东西。信件是周期性的,成交不是。
而且它和旗舰是同一条逻辑的两端 —— **信件给你数字,Discord 给你看这个数字被真的执行。**

### 反过来,信件里**不能**放什么

- ❌ 实时成交(那是 Discord 的命)
- ❌ 盘中 levels(同上)
- ✅ 但**可以放它们的事后对账** —— 「上周三 gamma 翻负我说了什么,后来怎么样」

> **这就是闭环 vs 开环的意义:Discord 卖发生,信件卖结论和复盘。**
> 同一批素材,两种形态,不互相蚕食 —— 而且**信件的对账反而让 Discord 更值钱**(读者看到实时播报后来真的被验证了)。
