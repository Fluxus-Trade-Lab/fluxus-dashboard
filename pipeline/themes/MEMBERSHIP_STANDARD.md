# 成员判定标准

*为什么需要这份文件:`audit_taxonomy` 能证明一个代码**解析得到**,`verify_members` 能证明它的业务描述**含关键词**。两道都过不了的那一关是「关键词命中但其实不该在」—— 目前防住它靠的是我人工看了 37 遍大市值票,**不可复现、不可交接、下次换个人就漏**。*

*这份文件把那 37 遍看的东西写成判据。*

---

## 〇、三道关的分工

| 关 | 由谁执行 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `audit_taxonomy` | 机器 | 代码在可交易宇宙里存在 | 它属不属于这个主题 |
| `verify_members` | 机器 | 业务描述含主题关键词 | **关键词命中但业务不对** |
| **本文件** | 人 | 该不该在 | — |

**已知的失败案例:CORT($120 亿)** —— 做 Cushing 综合征和肿瘤,却通过了 GLP-1 的关键词检验,因为我在关键词表里放了 `cortisol`。**相邻生物学不是同一个主题。**

## 一、通用判据(所有主题适用)

一只票要进某主题,必须**同时**满足:

### ① 收入判据 —— 主题业务是不是主要收入来源

```
✅ 该主题相关业务占收入 ≥ 30%,或是公司自述的主要战略方向
⚠️ 10–30%:只有在该主题成分股不足 8 只时才考虑,且必须在 note 里注明
❌ < 10%:不进,无论叙事多顺
```

**判例:AMGN 被移除。** MariTide 是 Phase 3 的真肥胖症资产、且是 Amgen 唯一的,但**零商业收入**;$2,222 亿的市值由 Enbrel/Repatha/Prolia 定价。

### ② 定价判据 —— 股价是不是被这个主题驱动

```
✅ 该主题的行业消息发布时,这只票会同向显著波动
❌ 它对主题消息无反应,只跟自己的财报/临床数据走
```

**判例:Biotech 整体降级为 XBI proxy。** 598 只成员,内部相关比随机还低 —— 每只跑自己的 FDA 事件。**「业务对」不等于「一起动」。**

### ③ 稀释判据 —— 它会不会淹没这个主题

```
❌ 市值 > 主题内中位市值的 20 倍,且主题成员 < 15 只
```

理由:主题按**中位数**聚合。6 成员的主题里塞进一只多元化巨头,它就占了六分之一的投票权,而它的波动多半来自和主题无关的业务。

**判例:AI - Datacenters 移除 AAPL/AMZN**(ETF 种子 AIQ 带进来的);**GLP-1 移除 AMGN**。

### ④ 流动性判据 —— 见 `pipeline/themes/__init__.py`

```
市值 ≥ $3 亿  且  日成交额 ≥ $200 万
```

**这条只作用于主题聚合,不作用于 universe 和 screener。** 一只 $9,000 万、日成交 $44 万的票是合法的 screener 命中,只是不该让它的陈旧报价塑造主题读数。

**判例:DPRO / UAVS / AIRO 从 Drones 移除** —— 都是真无人机公司,但都在门槛之下。

## 二、按主题类型的附加判据

### 业务主题(industry / etf 方法)

**必须能回答:「这些公司同时变好或同时变坏的那个共同原因是什么?」**

答不上来就不是主题,是标签。

```
✅ 铀:铀价 + 核电政策
✅ AI 数据中心:超大规模厂商的 capex 周期
✅ 铜矿:铜价
❌ Industrial Metals:Finviz 的残余桶,把不属于铜/钢/铝/煤的一切扔进去 —— 没有共同原因
❌ Telecom Services:42 家运营商,各有各的市场和监管
```

**残余分类(名字里有 "Other"、"Diversified"、"Miscellaneous")默认不建主题。**

### 因子主题(rule 方法)

**不适用「共同原因」判据。** 它们按属性定义 —— 微盘生物科技和微盘矿业股共有的只是一个数字。

要检验的是**规则有没有选出它宣称要选的东西**,由单元测试管(`test_themes.py::TestRuleThemesAgainstRealShape`)。

### proxy 主题

**只需回答一件事:这个基金是不是你实际会买的那个东西。**

```
✅ China Tech → KWEB   —— 你买的就是 KWEB,不是拼一篮 ADR
✅ Biotech    → XBI
❌ 不要为了「看起来完整」给一个你不交易的地区/资产建 proxy
```

## 三、加入新成员的流程

```
1. 拉业务描述(yfinance longBusinessSummary)
2. 对照 §一 四条判据逐条过
3. 通过 → 写进 extra,并在 note 里记日期和理由
4. 不通过 → 不加,并把「考虑过但拒绝」也写进 note
5. 跑 verify_members + build_groups,确认 audit CLEAN
6. 下次 validate_taxonomy 时看该主题 excess 有没有变差
```

**第 4 步不是形式主义。** 已记录的拒绝案例:

- **HIMS** —— 我记得它卖减重产品,但**它自己的业务描述里没提 GLP-1 或减重**。凭印象加进去,就是重犯 CORT 那个错
- **AMGN / CORT** —— 见上
- **DPRO / UAVS / AIRO** —— 流动性判据

## 四、拆分判据

一个主题验不过时,先判是哪一类:

| 类型 | 症状 | 处置 | 判例 |
|---|---|---|---|
| **映射错误** | 名字对,但映到了错的行业 | 换成手工名单 | Memory & Storage 映到整个 Computer Hardware:−0.002 → **+0.341** |
| **成分污染** | ETF 种子带进了不相干的大票 | 删掉 ETF 种子 | Drones/Space 被 ARKX 带进 AMD/AMZN/GOOG:+0.044 → **+0.101** |
| **伞形合并** | 把几个不相干行业合在一个名字下 | 拆 | Metals & Mining +0.047 → Steel **+0.202** / Coal **+0.199** |
| **概念不成立** | 拆到底也没有共同驱动 | **不拆,标 provisional** | Industrial Metals · Telecom Services · Packaged Foods · Computer Hardware |

**最后一类不要继续拆。** 拆到 n=4 时 excess 的噪声带是 ±0.032 —— 那是用测量误差换一个好看的数字。

## 五、成员冲突时听谁的

**当叙事和盘面冲突,以盘面为准。**(完整表述见 `taxonomy.py` 文档)

**判例:比特币矿工。** IREN/CORZ/WULF/HUT 已把大量算力转成 AI/HPC 托管,业务上属于 AI 数据中心。但实测:

```
与纯加密的相关   0.664
与 AI 数据中心的相关  0.484
```

**市场还在按加密给它们定价,所以它们留在 Crypto Equities。** 我们是按「怎么交易」分组,不是按「财报怎么写」分组。

两条防护:
1. **叙事定候选集,价格定成员** —— 否则这就不是分类法,是贴了标签的无监督聚类
2. **选成员和验证不能用同一段窗口** —— 否则是自证
