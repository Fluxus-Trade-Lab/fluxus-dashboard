# 每日临帖 Copybook 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让「每天把跟踪名单写的东西压成卡片 → 用户一行表态 → 双向落账」这套回路今天就能跑第一遍。

**Architecture:** 无代码。四个 markdown 文件 + 一段固定的浏览器抓取流程。名单的真相来源是 X 私密 list,不落盘;落盘的只有角色标签、每日判断台账、和入库的样本解剖。

**Tech Stack:** Markdown · claude-in-chrome(登录态浏览器,X list 时间线)· 无脚本、无 cron、无依赖

## Global Constraints

以下每条适用于所有任务:

- **分类法只有两套,不新建第三套。** 卡片上标**形态 1–9**(描述性,来自 `../../../Fluxus_Brand/research/Fluxus_Fintwit_Voice_Codes.md` §五,覆盖所有帖子);入 Swipe File 时归**文体 A–H**(规范性,来自 `../../../Fluxus_Brand/voice/Fluxus_Swipe_File.md`,只有值得偷的才配拿文体号)。两者是「描述」与「录取」的关系,不是竞争关系。
- **Swipe File 既有入库规矩不变**:每条解剖 ≤5 行;必须回答「装我的哪段素材」,**答不出不入库**。
- **bookmarks 是关键指标**(`../../../Fluxus_Brand/voice/Fluxus_Swipe_File.md` 头部:「bookmark 率 = 订阅意图,比 likes 值钱」)。X 时间线上拿不到 bookmark 数,**只在用户「存」之后,对那几条补抓帖详情页**。
- **靶子(靶)类内容永不进 Swipe File**,只留在 Ledger 的「杀」行。
- **预测必须在用户表态前写死在卡片列表末尾**,落账后不可修改。
- **提交需用户明确同意。** 所有 commit 步骤在用户说「提交」之前保持未勾选。
- **只抓公开数据,不订阅任何付费产品。**
- **用户每日耗时 ≤5 分钟**,超了就是设计失败,按 `../../../Fluxus_Brand/copybook/Fluxus_Copybook_Spec.md` §11 砍卡片量。

## YYYY-MM-DD(周X)
卡片 N · 存 a · 杀 b · 过 c
预测 #xx #xx #xx → **命中 m/3**
