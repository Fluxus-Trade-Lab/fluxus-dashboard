# 晨读三页 · 表面简报

**范围**:Dashboard / Themes / Screener+Watchlist 三页,作为一件东西设计。
**模式**:Operate。**世界已定**(墨底 #12110F、海报蓝红、Plex),这里只定结构与分工。

## 方向(Andy 2026-08-18 亲自定,压过骰子)

**就是三页,不合并、不做步进器、不做劈屏。** 三页各自回答一个层级的同一个问题:
**「什么在变?什么在强?」** —— 层级不同,问题相同。

| 页 | 层级 | 凸显什么 |
|---|---|---|
| **1 Dashboard** | 市场 | 市场读数 · 结论 · **market cycle** · 板块与主题的**一日 / 一周变化** |
| **2 Themes** | 主题 | **变化与相对强度**:什么是恒强的,什么是突然从后面加速。**四态(Leading / Weakening / Lagging / Improving)的存在意义就是这个** —— 强调主题的变化,**不是个股** |
| **3 Screener / Watchlist** | 个股 | 个股的**变化与 RS**。有的是单一个股在变,**有的是所在主题板块一起在变 —— 这是加分项**。此处需要 **TradingView 图**,看个股的月 / 周 / 日级别 |

## 三条由此推出的硬约束

1. **同一个问题,三个层级** —— 三页的骨架应当同形:先说变化,再说强度,最后给名字。
   不同的只是「谁在变」的粒度。
2. **第 2 页不许出现个股主角。** 主题层的产出是主题,个股只作为成分证据出现。
3. **第 3 页必须能回答「这只票是自己在动,还是它整片在动」** —— 板块共振是加分项,
   所以它必须是第 3 页上可见的一列/一个记号,不是要跳回第 2 页才能知道的事。

## 图表:用 TradingView widget(Andy 2026-08-18 定)

**不是新依赖 —— 已经在仓库里。** `frontend/src/components/ticker/TickerChart.jsx` 嵌的就是
官方 Advanced Chart(`s3.tradingview.com/external-embedding/embed-widget-advanced-chart.js`),
个股页在用,已处理明暗主题切换与 symbol 变更时的重挂载。

所以第 3 页的做法是**复用这个组件**,不是引入新东西。三条待办:

1. **周期**:现在写死 `interval: 'D'`,签名只收 `{ symbol, height }`。要月/周/日就得把
   `interval` 提成 prop,并在第 3 页给一个三档切换。
2. **触发方式**:名字那么多,不可能每个都挂一张图。图应当**按需出现**(选中一个名字才挂载),
   否则一页几十个 iframe。
3. **离线**:widget 走外链,断网时是空框 —— 需要一个「图表不可用」的诚实空态,
   不是白框。站点公开部署,没有 CSP,widget 的外链请求本来就已经在发生了。

## 共用骨架:卡片矩阵 + 尺寸分级(Andy 2026-08-18 锁定)

**骨架**:每页一组卡片,卡内三行永远同序 —— **变化 → 强度 → 名字/成分**。

**Andy 的修正,已并入骨架**:**卡片不等大。尺寸就是重要性,而且每页的重要性不同。**
这一条正好解掉这张骨架原本的风险(判决被降成并列项之一)。

> **尺寸是这套骨架的第四个通道** —— 三页共用顺序,各自决定谁最大。

各页的尺寸分级(由三页的分工推出,**待逐页确认**):

| 页 | 最大的那张 | 中 | 小 |
|---|---|---|---|
| Dashboard | **判决 + 证伪条件**(必须能独立截图) | market cycle | 板块/主题的一日 · 一周变化 |
| Themes | **四态与加速度的全景**(什么恒强 / 什么突然加速) | 单个主题 | 成分证据。**个股永不取得大卡** |
| Screener / Watchlist | **选中的那只票 + TradingView**(月/周/日) | 扫描格 | 名字 |

第 3 页的特殊性:**尺寸响应选择** —— 没选中时扫描格是主体,选中一只票后它连同图升为最大。
这也是「单只在动 vs 整片在动」那条约束的落点(灰点已做,4d9f83d)。

## ✅ 尺寸分级已锁定(Andy 逐页确认,2026-08-18)

| 页 | **最大** | 中 | 小 |
|---|---|---|---|
| **1 Dashboard** | **判决 + 证伪条件**(可独立截图) | market cycle · **Founders note** | 板块 / 行业 / 主题的 1D·1W 变化 |
| **2 Themes** | **四态象限全景**(领先 × 加速,76 条一张图) | 时间轴强弱曲线 | 成分证据。**个股永不取得大卡** |
| **3 Screener / Watchlist** | 扫描格 | **固定的 TradingView 卡**——默认显示某个筛选标准的第一只票 | 名字 |

三条随裁决产生的推论:

1. **第 3 页尺寸不响应选择。** 原提案的「选中即升为最大」被否 ——
   图是一张**固定卡**,位置不变,只换内容;未选中时它有默认票,不是空框。
   点一下不重排版式,这条同时消掉了原提案的重排风险。
2. **Founders note 留下,拿中卡**(Andy:「之前说要填写的 founders note 也是有必要的吧?」)。
   拿中卡不拿大卡的理由:它是这一页上**唯一不是算出来的东西**,该和 market cycle 并列;
   而它**大多数日子是空的**,一张空的大卡会让整页读起来像坏了 —— 而「空日」在这套系统里
   是合法状态(拒绝清单 §1),不该被版式惩罚。
3. **卡内三行顺序(变化 → 强度 → 名字/成分)是卡内的事**,不是页面的事。
   页面的顺序由尺寸决定,尺寸由 Andy 逐页定。

## Dashboard 各卡内容(本轮实现)

| 卡 | 变化 | 强度 | 名字 / 成分 |
|---|---|---|---|
| **判决(大)** | `conditions.history` 的日序列 —— 11/15 今日 vs 15/15 于 08-14。**这是这一页上唯一一条被存下来、带日期的变化** | `verdict.env` + `score` / 12 票 | `vote_detail` 十二枚记号(距离各自的线,单位各不相同)+ 证伪句 |
| market cycle(中) | 2 年 conditions 线 | 0–100 分与档 | 三个投票人里**最弱**的那个及其绑定条件 |
| Founders note(中) | — | — | 手写(日 / 周两档) |
| 变化带(小) | 基准 / 板块 / 行业 / 主题的 1D·1W | 各自窗口内的 RS 名次 | 代码与主题名 |

### 两处数据事实(做的时候查出来的,写下来免得下次重推)

1. **12 票的判决没有历史。** `breadth.json` 存了 100 天的**原始输入**(`history.rows`),
   但没存每天的 verdict.score。前端**不许**拿原始行重算票 —— 那是 `breadth_signals.py` 的活。
   所以判决卡的「变化」行用的是 `conditions.history`(15 项条件,存了 date + positive + score),
   **两个分母必须都印在界面上**,不许混成一个数。
2. **`vote_detail` 早就在 payload 里,而 Dashboard 一直在渲染降级版。**
   `VoteGlyphs`(四通道:填充 = 站哪边 · 线 = 翻转点 · 高度 = 距离 · 虚线 = 没测出来)已经写好,
   Dashboard 用的却是只有一个 bit 的 `VoteMarks` fallback。本轮换成 `VoteGlyphs` ——
   证伪条件本来就该由这张图承担,不该由一句话承担。
   **不许跨票排名**:0.048 的 ratio、137 只、−2.53 点不是同一个东西(高度已在各自量程内归一)。

### 一条必须写进图里的事实

**四态就是这张象限本身,不是它的一种画法。**
`pipeline/themes/rs_engine.py:180` 的 `classify(excess_3m, rs_accel)` 两轴都在 0 切;
拿 75 条全量复算,**75/75 一致,零不一致**。

两条直接推论:

1. **点不许按 state 上色。** 位置已经说了 state,上色是同一件事印两遍 ——
   和 08-16 删掉 Field 层的是同一条理由。四个象限的名字写在四个角上,连计数一起,
   于是表头那排 census chip 也不必再存在。
2. **象限固定读 3M,不跟顶上的 1W/1M/3M 开关**(Andy 裁决),并且**这句话要印在图上**。
   让开关也切 x 轴的方案被否掉了,因为那会让点的位置和 payload 的 `state` 字段打架 ——
   一个点可能落在 Leading 格里却标着 Weakening。

## Screener / Watchlist 各卡内容(Andy 2026-08-18)

| 卡 | 内容 |
|---|---|
| **扫描格(大)** | Watchlist 的十二张 scan 卡 / Screener 的表。这一页的活是**发现**,所以答案的场地最大 |
| **TradingView(中)** | **固定卡**:位置不变、尺寸不变、永不空。默认 = **True Market Leaders 的第一只**(Andy 亲定的筛选标准)。月/周/日三档 |
| **名字(小)** | 卡内的票、表里的行 |

**两个入口共用同一张卡、同一个名字**(`useChartPick`,localStorage)。它们是同一件事的两扇门,
一张图在两扇门后说不同的话,就是两台仪器穿一件衣服。

### 为什么 TML 当默认(写下来,免得下次问)

它的配方是 `liquid_leader ∧ 本主题/行业 state = Leading ∧ rs_1m ≥ 80` ——
**这一页存在的那个问题(这只票是自己在动,还是整片在动)已经写在它的准入条件里**。
所以图一打开就停在「整片在动」里最强的那只。顺序取文件自带的(hybrid_rs 降序),
前端不许自己重排一个「更好的」默认。

### TickerChart 三条待办已做完

1. **`interval` 提成 prop** + 月/周/日切换(原来写死 `'D'`,签名只收 `{symbol, height}`)。
2. **按需挂载** —— 但 **IntersectionObserver 只是加速,不是闸**。
   第一版拿 IO 当闸,而在内嵌浏览器里 IO **一次都不触发**(自建探针在可见元素上 600ms 零回调),
   图于是永远不出现 —— 一个静默的空框,正是离线态要防的那件事。
   现在是 `getBoundingClientRect` 当判据,IO / scroll / resize 都只是加速。
3. **离线诚实空态** —— 斜纹盒 + 明说是「离线」还是「脚本被挡」。
   **消息和 widget 必须是兄弟节点,不能共用一个槽**:embed 脚本会异步清空它被挂进去的节点,
   两者共槽时,飞行中的旧脚本会把消息本身擦掉(实测:斜纹盒渲染了,里面的 `<p>` 没了)。
   widget 那个节点还带整份配置当 key,于是旧脚本只可能清到一个已被 React 卸下的节点。

### 一处口径修正

芯片条印的是 **`25 of 27 · 2 not listed here`**,不是 `25`。
TML 面板带 `count: 27` 与 `truncated: 2`,把数组长度当筛选结果的规模印,就是静默截断。

## 短名单托盘(2026-08-18)

`hooks/useShortlist.js` · `components/shared/ShortlistTray.jsx` · `PickedChart` 加两扇门。

PRODUCT.md 把晨读的**动作**写成「就地做今天的短名单……需要选中/标记/带走的机制,并且要记住选了谁」,
而仓库里一个字都没有 —— 三页读完是个断头。托盘拿**小卡**:它是这一页的产出,不是主体。

**两扇门,和为什么不是第三扇。**
① 图卡上的 `add to shortlist +` —— 你看完图,决定就发生在那里。
② 图卡上的 type-ahead,盖住今晚文件里的**所有**名字(不止 TML 那 25 个)。
**故意不做「点格子里的名字直接进图」**:那个格子 90px 里已经装了代码、主题记号和一个数,
第三个目标会把两个手势都做坏。用键盘够到一个名字很便宜。**这条留着等 Andy 反对。**

**三条纪律**:
- 每条记录**冻结加入当时的读数**,并带上它来自哪个筛选。一周后问「这个判断好不好」,
  要的是那天的样子,不是今天的样子。刷新它等于偷偷改写理由。
- 短名单**属于一个日期**。存的是当时那份文件的 date;来了更新的文件就明说
  「这份是照 08-11 那个收盘做的」并给一键清空,**不许换上今天的衣服蒙混过去**。
- 存 localStorage,并在界面上**明说**它不跟人走。PRODUCT.md 里存哪儿仍是未定;
  记录是一个扁平数组,接 Google Sheet 是加一个 writer 不是重写。

### 一个当场撞出来的 bug,值得记

第一版 `useShortlist` 是普通的 `useState` hook。**第二次被用到就错了**:图卡加了一个名字,
它自己那份 state 更新了,旁边的托盘继续说列表是空的。
**两个组件为同一个事实各存一份 state**,和这套编码系统一直在赶走的毛病是同一个,
药也一样 —— 一个大家都订阅的源。`useSyncExternalStore` + 模块级 store,
localStorage 只当持久化,**永远不当两个活着的组件之间的通道**。
