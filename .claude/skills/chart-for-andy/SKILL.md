# chart-for-andy — 照抄，别重新发明

**这是方法不是教训。** 2026-09-02→09-06 建 Rotation 三卡（Terrain / Momentum & Acceleration / Flux），Andy 逐轮改了二十来次。下面每一条都是他裁过的，照抄能省掉大半轮次。

## 开工前

- **一句话说不清就别画**（他的原话）。先写「这张图回答什么」，写不出来就是图还没想清楚，不是画得不够好。
- **一张卡一个视觉基元**：点 / 线 / 面。三张卡凑成点线面，比三张各自漂亮更成立。名字也照这个取。
- **先读已有规划**：同一块地皮常常已经挂过号（Library 就挂了两次），分两轮建第二轮必推翻第一轮。

## 轴与量程

- **纵轴定死，加线不重算刻度。** 他第一个否掉的就是「点第二个主题时 Y 轴高度开始变」。
- **超出量程用软削波，不用裁剪**：量程内线性（标注的网格线必须是真的），超出部分按 `x/(1+x)` 压进边框内一条带，渐近线够不着顶。tanh 饱和太快，40% 和 100% 会落在同一个像素。
- **只画控件够得着的那段**。档案有 90 个交易日、下拉最远十周，就从十周画起——多出来的那段没人能选。
- **图高跟视口走**：`clamp(360px, calc(100vh - 210px), 620px)` + `preserveAspectRatio="meet"`。屏幕矮的人看到的是缩小的整张图，不是被裁掉一块。

## 标注

- **前五 + 后二写名字，中间淡出。** 不是全标（乱）也不是全不标（读不出）。
- **点的大小随数值**：领先的更大、占的空间更大。视觉排序和数值排序必须一致。
- **名字离点远一点、字号大一点**，引线可以不要；名字之间强制最小间距互相推开。
- **先看到点，再看到字。** 他原话「我先看到的是文字而不是点和点之间的比赛」——字太黑太大就是这个病。

## 颜色与语言

- **配对色 + 墨认线，永不用灰阶区分**：两个灰读者分不清。灰阶只留给有序的态。
- **一次只说一种语言**。中英混排他直接否。所有面上的字走 i18n；量名（RS 0–2w / Acceleration）两种语言都保留英文。
- **全局 `svg{width:100%}` 只许挂在图表容器的 class 上**，图例图标用 CSS 画。

## 交互

- **每张图都要能悬停读真值。** 线弯了、值被压了、点被淡化了都行，**数不许弯**。
- **展开用「+」，不写"展开·谁在哪一态"**。show don't tell——他删过好几处这类指示语。
- **卡上不写说明**；口径和算法进折叠的 How to read。
- 两栏布局里的展开面板要**通栏**，挤在半栏里会把邻卡撑高。

## 命名（09-06 那轮，三条都是被他改出来的）

- **词说读者的收获，但不许承诺量没在测的事。** 「转折」被换成「加速度」：转折承诺方向改变，而那个数只说"这周比前三周快"，一个一直在加速的主题连着几周为正、一次转折都没有。
- **起标签名前先 grep 数据字段。** 一轮里撞了两次：`persistence` 想拿来标季度超额，可它本来就是「五个时间尺度里有几个在领先」；`RS 0–1w` 想拿来标加速度，可 `rs_0_1w` 就是本周超额，而隔壁那栏写着 `RS Last 2 weeks`，并排会被读成同一种量的两个长度。**同名两个量比名字难听严重得多。**
- **量名用白话的 last N weeks，不用行话**：`RS Last 2 weeks` / `RS This week vs prior 3` / `RS Last 13 weeks`。他要求英文前统一带 RS。不是单个窗口的量，就写成对比式，别硬凑成窗口。

## 排版的两条硬账

- **长标签压缩，不缩全局字号、不截断**：量出最长的那条（canvas measureText，页面自己的字体），超出可用宽度的用 `textLength` + `lengthAdjust="spacingAndGlyphs"` 压进去。只有个别名字会触发，其余保持原字号。为两个名字把三十个都缩小是赔本的。
- **画布宽度 ≈ 它在屏幕上的像素宽**，字号单位才等于渲染像素（370 单位的画布落在 369px 的栏里，13 单位渲染成 13.0px）。想要 13px 就把画布调到那个宽度，别去猜缩放。

## 字体与可读性（09-11 Market State 那轮，Andy「大多都是同意粗细字体，颜色相近」）

- **先量再改**：headless 浏览器逐文字节点统计「字号×字重×颜色」按字数占比，别凭眼睛。那次量出 72% 的字是 11px 常规浅灰、最该读的证据句在最小最浅一档。改后复量当验收（72%→36%）。
- **一个角色一档**：读的内容 13px 次灰、句中数字墨色半粗（Figures 组件：名字里的数字如 T2108、20-day 不加粗）；标签 13px 半粗墨色；11px 只给卡片标题、图表标签、注释。
- **token 名字不可信，要量**：全站 `--color-text-bold` 浅色主题比正文还浅（13.3 vs 15.3），90 处「强调」都更弱，几个月没人发现。
- **同一个数只印一次**：并卡/删砖前逐字段核对被删的那块有没有独有的数（Classic breadth 的 A/D line 表里没有 → 先加列再删）。
- **Andy 明说要注释时就加注释**：「卡上不写说明」是 Themes 那轮的默认；他 09-11 对 Correction risk 说「尽量配上图表，再加上注释」——最新的话赢。每张图下一两行：数怎么来、样本哪年起、深浅/框线代表什么。
- **浏览器面板被他隐藏时**：截图会返回空白帧，别重试；用 `playwright-core` + `~/Library/Caches/ms-playwright/chromium-*` 自己 headless 拍（装在 scratchpad），能点开折叠、截元素、零页面报错核对。
- **交给他看之前自己先截一张挑毛病**：09-11 自查出中英混排、12 个字形截断、证据重复印两遍，三处都在他看到之前修掉。

## 一条反面结论也是方法

**"突然加速"不要标记。** 涂色段、空心圈、线加粗、小竖线——四种都做过，他四种都否了，最后定的是**不标，让悬停承担**。下次遇到「想在线上标出某个事件」，先默认不标。

## 取数的坑（踩一次就够了）

- **日内线要用 `period=`，不要用 `start`/`end`。** yfinance 的 5 分钟线只给最近 60 天，而给定起止日期时**只要跨度超过 60 天，Yahoo 整单拒绝、返回空表**，报的是「possibly delisted; no price data found」——长得像这只票退市了，不像窗口越界。`period='60d'` 拿得到完整 60 天。（09-25 实测，52 只票各踩一次；错误原文里那句 "The requested range must be within the last 60 days." 才是真因。）
- **拿不到就是拿不到，别把限制说成 bug**：4 月的 5 分钟线在 Yahoo 这条路上不存在，要更早的日内线只有 IBKR（`pipeline/ibkr.py`，需要本机 Gateway／TWS 在跑）。
- **图要能重跑，就把 CSV 冻进仓库**（`_pdf/.chartcache/` + `git add -f`）。窗口过期之后，脚本仍然出得来同一张图——这是"以后还能改这张图"的唯一保证。
