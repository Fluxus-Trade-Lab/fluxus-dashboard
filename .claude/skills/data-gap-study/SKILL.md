# data-gap-study — 一个缺口咬到哪些研究

2026-09-17 为半个字母表的缺口（`ticker_events` 06-26..08-07 只有 A–L）跑过一次：判了 13 个研究目录，没有一个结论翻转。产出 `data/research/half_alphabet_reach_2026-09-17/README.md`。

**为什么要有这套**：事故的后续（「把 universe 重报一遍」）曾经挂了 16 天没人认领，不是没人愿意，是**没有程序**。

**什么时候跑**：任何一次覆盖缺口 / 口径断裂被宣布之后，对 `git grep -l <归档名> -- data/research` 命中的每一个研究跑这四步。

## 四步

1. **日期**：逐个研究数它在窗口内用了多少样本行——**读脚本真正的 loader，引 `file:line`**，别按目录名猜。用的是研究**跑那天**的缺口形状（08-07 是后来才补算的）。
2. **继承**：每一个派生归档，读写入端的回看常数（`HEAT_WINDOW`、`rolling(n)`、lookback days）——**日期在窗口外不等于干净**（shortlist 的 heat seat 一直脏到 08-28）。还要查那些 ticker 名单来自脏归档的缓存（`event_bars.pkl`）。
3. **剔窗重跑**：**先复现已发表的那个数**，复现不出来先停下查为什么；复现得出来再剔掉窗口重算。
4. **分开两个原因**：在**干净**的日期里只保留幸存的那一半（A–L）再算一遍。符号与全样本相同 ⇒ 翻转来自窗口那段的行情，**不是缺的那一半**。

## 怎么跑

- **Fan-out**：4 个只读 agent 按批分工，然后**独立复核 3 个头条数字**，再动笔写。
- **C 级文档在顶部加横幅注明**（banner），**永不改写原来的数字**。
- 发现**未申报的污染** → 写 `DATA_CONTRACTS.md` §七 一行指名路由给该归档的 owner 线，并在任务板上开一件给他：`taskboard.py new --owner <名> --type data_gap_study --title "<一句话>"`。

## 产出

`data/research/<主题>_<日期>/README.md`：缺口是什么 · 命中哪些研究 · 每个研究判什么（受影响/不受影响/翻转）· 证据（file:line 与重算的数）· 谁还欠什么。
