## 一、今晚的主线：三个存活点栽在同一件事上，而它跟测试勤不勤快无关

三条比较符，`>=` 与 `>` 的差别只在**恰好等于阈值**那一点；三条格式串，`*100` 与 `*101`
的差别只在**进位跨过 .5** 那一格。这两件事都不是「谁忘了写测试」——
**是那个点得先够得着，测试才可能存在。**

我为此把全仓 18 道闸里所有数值阈值都量了一遍（`k/n` 能不能正好等于那个 double，n ≤ 20000）。
**结论跟我开工时想的相反：**

| 写法 | 数量 | 能不能踩到 |
|---|---|---|
| **字面量**（`TOLERANCE = 0.15`、`OK_RATE = 0.90`、`FACTOR = 1.5` …） | 14 | **全部可达** ——`3/20` 就是字面 `0.15`，`9/10` 就是 `0.90`，`3/2` 就是 `1.5` |
| **在比较处现算**（`audit_calendar_gaps` 的 `have_feed >= (1.0 - universal_frac)`） | 1 | **不可达** |

> **判据不是「这个阈值精不精确」，是「它是不是一个字面量」。**
> `k/n` 是**一次**除法，结果舍入到最近的 double，而字面量 `0.15` 解析出来的正是同一个 double——
> 所以一个写死的阈值几乎总踩得到。
> 而 `1.0 - 0.8` 落在 `0.2` **旁边那一个** double（`0.19999999999999996`）上：
> n ≤ 20000 全扫**零命中**，最接近 0.2 而不等于它的比值（4000/19999）差 **1e-5**，
> 那附近相邻 double 的间距是 **2.8e-17**——差十二个数量级，票数再多也够不着。
> 这道闸写着「至少 20% 的票有 bar」，而 **20% 这个点，它永远碰不到。**

⚠️ **这一节我连写错两版，都是自己量完推翻的**，写下来因为错的方向有用：
第一版写「0.15 在二进制里不是 0.15，任何真实份额都落不到线上」——错，`3/20 == 0.15`；
第二版改成「只有 base=0.0 这一条反常的路可达」——还是错，
`abs(0.30 - 0.15)` 也**正好**是 0.15，而 0.30 的滚动中位配 0.15 的份额是再普通不过的一对。
**`universe_shape` 的边界一直是够得着的，只是没人去够**；
而随手一构造（`0.65 - 0.50`、`0.50 - 0.35`、`0.40 - 0.25`）**全部算出 `0.15000000000000002`**，
比 0.15 大 2e-17，于是真代码和变异体一起报 U1——看着像测了，其实什么也没判。

**所以三个存活点是三种不同的病，不该合成一句话：**

| 存活点 | 真正的病 |
|---|---|
| `calendar_gaps` [22] L258 `GtE -> Gt` | **边界不可达**。测试必须显式传 `universal_frac=0.5`（5/10 正好落线），这不是取巧，是唯一的办法 |
| `universe_shape` [39] L92 `Gt -> GtE` | **边界可达，但顺手构造会差 2e-17**。选 0.25（减法下逐位精确）是为了让下一个读的人不用再踩一次 |
| `universe_shape` [43]/[48]、`calendar_gaps` [75]/[95]/[98] `100 -> 101` | 跟阈值无关：`:.0f` **正好把变异体加的那 1% 扔掉**。`0.15*100` 印 "15"，`0.15*101 = 15.15` 也印 "15" |

### 同一个坑 09-02 记过，形状一模一样

09-02 Zac 写过：漂移 0.2692 在 `*100` 下印 "27"，`*101` 下**也印 "27"**，
「对真代码和变异体都绿」。今晨我自己现场又栽了半次——
`test_the_share_a_d1_reports_is_the_share_that_was_measured` 断言 `"30%"`，
看着像在钉那个乘数，**其实杀不掉 `100 -> 101`**：`0.3*101 = 30.3`，`:.0f` 照样印 "30"。
断言一个百分数，和钉住那个乘数，是两件事。
能分开的份额要**算出来**：`f == 1.0` 对任何 n 都分得开（100 vs 101），
D3 只在阈值下方触发所以 100% 不可达，改用 `1/8 = 0.125`（印 12 vs 13）。

## 二、`audit_universe_shape` 18 个逐条判词

### 真洞，已钉住（17 个）

**⭐ [32] L64 `Gt -> GtE` —— 这一个就是统计量的定义**

```python
return sum(1 for t in ts if t[0].upper() > split.upper()) / len(ts)
```

翻成 `>=`，L 开头的票被算进「L 之后」。**全套测试对它是瞎的**：
`AL` 是 A 开头、`MZ` 是 W 开头，两个在 `>` 和 `>=` 下都不换边，
`test_the_split_letter_is_not_baked_in` 用 split="B" 配 A/C 名，同样不换边——
**19 条测试里没有一只 L 开头的票。**

为什么不是吹毛求疵：L 是盘上最忙的首字母之一（LLY / LIN / LMT / LOW / LRCX）。
把它们算到远侧，**份额和它要比的滚动中位一起被抬高**，于是漂移反而变小——
一次 M–Z 截断会被「还算在远侧的 L 票」部分吸收。
这道闸存在的全部理由是 docstring 那句：

> A source that is cut in half along a CONTENT dimension is flawless under every COUNT dimension check.

**把内容维量偏一个字母，就是同一个失败往里一层。**

**⭐ [29] / [37] L89 `len(prior) < 3` —— 第四场是第一场有资格被判的**

两个变异体（`< -> <=` 和 `3 -> 4`）做同一件事：把「可以开口」推到第五场。
而 U3 是 warning、**永不致命**——所以落在任何归档**第四场**的截断，
会被报成「历史不够，不判」然后放过去。
docstring 自己说这是最坏情形：一开头就截断的归档，毒化其后**每一场**的基线。
