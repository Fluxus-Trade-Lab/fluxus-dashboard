## 过程里撞上的三件事

### 一、`gap_pct` 只有一天的历史，而「零」和「没有」长得一模一样

`gap_pct` 和 `avg_vol50_prev` 是 **09-18 当晚**才写进 `universe.json` 的——和这个筛子同一天注册。
在那之前 129 场快照里这两个字段的覆盖率**全是 0.0**。

第一版回放老老实实调 `ep_qullamaggie.passes()` 逐场跑，读数是：

```
pass_big : total 0  median 0  zero-sessions 130/130
```

**130 场全 0。** 而 `passes()` 对缺输入的行返回 `False`——
这个「全 0」说的不是市场没有跳空，是**字段还没出生**。
行数、场次数、覆盖天数这些计数类检查对它全绿（`DATA_RELIABILITY` §六.7 同形，
`pitfall_having_a_row_is_not_having_data` 同形）。脚本里那条覆盖率打印是唯一报出它的东西，
而它是照着这两条旧账**先**写进去的，不是事后补的。

⚠️ **给以后任何要回放这个筛子的人**：`git show <sha>:data/output/universe.json` 里
**09-18 之前没有 `gap_pct`**，直接跑 `passes()` 会安静地还你一串 0。

### 二、绕过去的办法：两条腿分别重建，用唯一那场当阳性对照

有历史的字段够把 gap 腿**精确**还原：

```
open        = close / (1 + from_open_pct)
prior_close = close / (1 + change_pct)
gap_pct     = open / prior_close - 1 = (1 + change_pct) / (1 + from_open_pct) - 1
```

**阳性对照**（2026-09-18 是唯一同时持有原生字段和三个输入的场次）：

| 腿 | 做法 | 对照结果 |
|---|---|---|
| gap | 上式重建 | 5,306 行逐行比：绝对误差中位 **2.8e-5**、p95 2.8e-4。按 ≥10% 分类**逐票零分歧**——全宇宙 23/23，≥$1B 0/0，两个方向都没有出入 |
| ADV | `avg_volume`（Finviz）顶 `avg_vol50_prev` | 全宇宙 **17 只 vs 原生 16 只**，多出 `SLND`，一只没漏。但全场 5,258 行的 ≥1× 判定只同意 **91.5%**——这条腿是**代理，不是重建** |

所以 `rgap10_big`（gap 腿，精确）当**上界**报，`rpass_big`（含代理腿）并排放。

⚠️ **代理腿的对照日不具代表性**（反驳 verifier 指出）：09-18 是季度四巫日，
≥$1B 的 `volume/avg_volume` 合计 1.895，A 段中位只有 0.98——那天九成大票都轻松过了 1× 线，
所以「17 对 16 一只没漏」说明不了它在**平常日子的阈值附近**准不准。
能说明的只有 91.5% 这个数。**影响已量过并封顶**：C 段 61 只 gap≥10% 的 ≥$1B 票里，
成交量落在 `0.7–1.3× avg_volume` 的只有 **3 只**（08-19 CNL 1.12、08-27 TE 0.90、08-31 AIIR 0.85）——
代理腿最多挪动 58 中的 3。不改变任何一句结论，但「命中数」那列带这个误差，「gap≥10% 数」那列不带。

### 三、时钟对了，货不对——闸①挡不住的那一类

按 `last_completed_session(ET)` 给快照定场次是对的（02:12 ET 的快照装的是上一场，
`population_break._et_day` 09-19 修过）。156 个提交里 **28 个**的标签与其提交日不同，其中两个
若按提交日算会**撞上另一场的真快照**。这道闸是承重的，不是装饰。

**但它按钟走，看不出货装错了。** 写于**周一 04:17 ET** 的快照，时钟判它属于上周五——
而它装的是**周一的盘前**。本轮初版因此把 08-14 那格印成 `rgap10_big=15 / rpass_big=0`：
那份 payload 里最大的「跳空」是 ALG +52.8%，**成交 12 股**；同一场另外三份快照一致读 8 只
（`BRUN ETON HTFL LPTH NU RCAT RDDT UMAC`）。**一个 0 是假的。**

**补的闸**：`volratio = sum(volume)/sum(avg_volume)`，只在 ≥$1B 行上算。
阈值不是调出来的——它落在空档里：

| | 快照数 | volratio |
|---|---|---|
| 盘前 payload | 5 | 0.0018 – 0.0029 |
| **正常收盘** | **143** | **0.709 – 1.895** |
| 07-15..24 `avg_volume` 断供 | 8 | 77.0 – 304.0 |

下界取 0.5、上界取 3.0，两边各空着 **241 倍**和 **41 倍**。
选场同时改成**按快照时间戳取最新的可用那份**，不再按 `git log` 的提交顺序——
08-18 当初留下盘前那份纯粹是排序运气。排除口径也从正文搬进脚本（每场带 `ok` / `why` 两列），
免得有人重读 CSV 时拿到没过滤的 29 场。

**这条是反驳 verifier 逼出来的**，不是我自己查到的。
