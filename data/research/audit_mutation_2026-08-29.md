## 一句话

**我们最贵的那道守卫 `I6a`，自己一条测试都没有。** 把它的 `!=` 改成 `==`（判据完全反转），全套测试照样绿。
病根是现有三条测试**全部传 `output=None`**，于是整个 `reconcile()` 与 `ticker_shells()` 一行都没被跑过。
补 18 条测试后，`audit_archives` 的变异杀死率 **23% → 41%**，18 个新杀掉的里**危险逻辑变异全部覆盖**。

## 二、方法：给「先证明能报阳性」这条规矩装一台机器

宪法要求每道守卫带阳性对照（Growth Gary 08-25：**没有先验证一个检查能报出阳性，就不该信它的阴性**）。
这条一直是**手工**执行的，一次一条。这轮把它批量化：

往守卫源码里注射一个小的语义突变（`>=`→`>`、`and`→`or`、去掉 `not`、常数 +1、`True`↔`False`），
只跑这个守卫自己的测试文件，看有没有东西变红。

- **被杀掉的变异** = 这一行确实被测试钉住了。
- **存活的变异** = 这一行**可以是错的，而仓库里没有任何测试会说话**。存活不等于 bug（有等价变异），但每一个都是没被钉住的行。

刻意保守：**不做语句删除、不换返回值**——那类变异会因为崩溃而「被杀」，把杀死率抬成一个没有意义的数。

## 四、补了什么 + 回执

`pipeline/tests/test_audit_archives.py` 从 3 条加到 **21 条**（新增 18 条，只碰测试文件，生产代码零改动）：

- **I6a** 四条：计数一致不报 / 不一致报（用 08-25 那个形状：页面 4 vs 归档 8）/ `measured:false` 的面板不参与对账 / 别的场次的行不算这一场
- **I6b** 四条：一致 / 不一致 / **缺 JSON 是跳过而不是当成 0 行**（否则每个不导出的筛子都会误报）/ 只对最新场次
- **I6c** 两条：一致时静默 / 不一致只是警告不是违规
- **I7** 七条：零壳静默 / 恰好 10% 是警告 / 超过是违规 / 没有 `ohlc_2y` 键算壳 / 读不动算壳 / `_` 开头的不算 ticker 文件 / 没有目录是警告
- **`main()`** 一条：有违规时那一行必须以 `BAD` 开头

再补 13 条钉 **I4（每场行数上下限）/ I5（陈旧度）/ I3（只对 breadth）** 的边界——
这一层是**警告级**，不进 exit code，但它决定「什么时候只是记一笔、什么时候该有人去看」：

- **I4**：恰好在下限（`0.30 × 中位 = 3` 行）**不报**、差一行就报；恰好在上限（`3.0 × 中位 = 30`）**不报**、多一行就报；
  六个场次够判、五个不够；`counts=False` 的归档永远不判
- **I5**：最新场次**等于**上一个完成场次时静默、落后一场才报；只有表头的空归档不进这个检查（`max()` of nothing 正是它以前崩的地方）
- **I3**：两个**都是有效交易日**的行 spx_close 相同 → 报并可修（此前这条路径总被 I1 遮住）；别的归档带 `spx_close` 列**不算** breadth

**回执（每补一批就重跑一次普查）**：

| | 杀死 / 变异体 | 杀死率 | 测试数 |
|---|---|---|---|
| 起点 | 23 / 101 | 23% | 3 |
| 补 I6 / I7 之后 | 41 / 101 | 41% | 21 |
| **补 I4 / I5 / I3 边界之后** | **54 / 101** | **54%** | **34** |

第二批新杀 18 个，**七行危险变异全部在内**（L159 / L164×2 / L174 / L177 / L181 / L182 / L190 / L232 / L242×2 / L250 / L265）；
第三批新杀 13 个，**I4/I5/I3 的边界全部在内**（`COUNT_FLOOR` / `COUNT_CEIL` 两个常数、`>= 6` 两种变异、
`<` 与 `>` 三处、三个 `and`、`not in`、I5 的 `<`）。
这就是这两批测试的阳性对照：**它们不是「加了会绿」，是「守卫坏掉时它们会红」**。

## 五、还没钉住的 47 个（下一批的清单，本轮不做）

| 区域 | 存活数 | 性质 |
|---|---|---|
| `ARCHIVES` 配置表（L54–72） | 19 | 每个 `"counts"` / `"nightly"` 布尔翻转都是真语义（会开关某个归档的 I4/I5 检查），但影响面是配置不是判据。**要钉住需要给 11 个归档各配一组夹具**，性价比最低 |
| `audit_one` 主体（L73–145） | 12 | 只剩滚动窗口的常数（`-21:-1`、`iloc` 边界）与消息格式 |
| `ticker_shells` / `main`（L226+） | 7 | 含一个纯装饰的 `len(shells) > 12`（省略号） |
| `repair` / `run`（L196–225） | 5 | |
| `reconcile`（L146–195） | 4 | try/except 分支与消息格式 |

**两个已判定为等价变异（存活但不是缺口，不要再花时间）**：

- **L121 `len(per) > 21` → `>= 21`**：只在 `len(per) == 21` 时两分支才可能不同，而那时
  `per.iloc[-21:-1]` 与 `per.iloc[:-1]` **取到的是同一组 20 个值**。无法用测试区分。
- **L249 `len(shells) > 12`**：只控制消息末尾要不要加省略号，纯显示。

**建议顺序**：`ticker_shells`/`main` 与 `repair`/`run` 的 12 个（有真判据），配置表那 19 个最后。

## 六、工具本身的一条教训（写进它的 docstring 了）

第一版让变异**直接写仓库里的源文件**，在 `finally` 里还原。跑到一半被超时 kill，
`git status` 里就留下了一个被改写的 `audit_unpushed.py`（43 增 65 删）。
**只在没出事时才会跑的清理，不是清理。**
现在每个变异体活在临时工作区的 `pipeline/` 副本里（`data/` 走符号链接，测试本来就用 `tmp_path`），仓库永远不被写。

## 七、这个工具不是闸

`audit_mutation_sweep` 的退出码恒为 0。要把它变成 CI 闸需要一个「存活预算」，而我们还没有基线；
先让它当量尺跑几轮，攒出各模块的正常区间再谈。
