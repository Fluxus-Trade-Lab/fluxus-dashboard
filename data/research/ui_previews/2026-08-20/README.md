# 预览稿 2026-08-20 · watchlist 的 ATR 位：「线下方」和「没测出来」现在长得一样

**只出预览稿，`frontend/` 一行没改。**

## 一、现在是什么样

`WatchlistPage.jsx:335` 的 `atrFill` 在两种情况下返回 `null`：`v < 0`（在 50 日线下方）和 `v == null`（没测出来）。两者都落回同一个 `--color-text-bold` 纯文字 ticker。

先更正一条记忆：`todo_watchlist_ui_fields` 里写的「ATR 徽章负值会全绿（配色缺负分支）」**已经不成立** —— `66d4d6f` / `01bf587` 之后负值早就不上色了，tooltip 也分了负值分支（`:370`）。

留下来的是另一个洞，正好是仓库自己的 pitfall`一支 token 两个职责`：**「我量过了，它在均线下方」和「我不知道」用同一个外观说话。** 前者是可交易的读数（该去别的格找它），后者是数据缺口（该去查 pipeline）。读者分不出。

## 二、量过的（成对量，不是只量对背景）

在预览稿这份**简化版** ramp 上（没有实现线上 `atrFill` 的 `toLightness` L\* 修正）测的：

| 关系 | light | dark |
|---|---|---|
| ticker 墨对色块（最差点） | **3.95:1**（ATR 9） | 4.79:1（ATR 6） |
| 负值短横 / 空心点边框 对面板底 | 8.30:1 | 7.92:1 |
| v2/v4 轴线 对面板底 | 1.51:1 | 1.37:1 |
| v3/v4 折底行（62% 不透明）ticker 墨 | 3.44:1 | 5.78:1 |
| **ramp 相邻档彼此**（1↔3 / 3↔5 / 5↔6 / 6↔8 / 8↔10） | 1.25 / 1.23 / **1.06** / 1.32 / 1.62 | 1.57 / 1.28 / **1.11** / 1.34 / 1.22 |

两条要说的：

1. **ramp 相邻档彼此只有 1.06–1.62:1。** 颜色能给"哪一档"，给不了"哪个数"，也分不开相邻两档 —— 这就是 v2/v4 用**位置**当主通道、颜色当第二通道的理由。（这是「量过只覆盖你查的那一个关系」：以前量的是墨对底，没量过档与档。）
2. light 模式 ATR 9 处 ticker 墨掉到 **3.95:1**（墨的切换点晚了一档）。**这是在简化 ramp 上测的，不是对线上代码的断言** —— 线上有 L\* 修正，数值会不同。要不要动，得先对着真 `atrFill` 复量一次；我今晚不改前端，只把这条记下来。

扣分扣在哪：

- **v1「让推理被看懂」−1**：短横「下沉」的语义要回图例查；页面上说不出「为什么下方就不上色」。
- **v1「决策优先」−1**：线下方的票仍混在名单中间，要逐行辨认。
- **v2「简洁整齐」−1**：每行多 64px 的轴，一行从 3 个元素变 4 个；8 行好看，25 行一格会密。
- **v3「文案只留交易内容」−1**：多了一行「在 50 日线下方 · 2 只」的小标题 —— 是分组说明，不是读数。
- **v3「让推理被看懂」−1**：折底解释了「下方」，「未测量」仍只有一个要查图例的空心点。

没有一版触到判负条件（新增颜色 / 鸡汤文案 / 动效），三版都进了第二轮。

## 五、v4：胜出的 v2 + 从落后两版偷来的点

- 轴从 64px 收到 **56px**，方块 6px（v2「简洁整齐」那 −1 的直接补法）；
- 线下方的票**折到格底**、62% 不透明（偷 v3 的「决策优先」）；小标题只留「50 日线下方 · N 只」，是分组依据不是文案；
- 未测量不再是一段空白，而是**轴位置上的空心点**（偷 v1）—— 空白和「渲染坏了」长得一样，一个点不会；
- 方块仍按 0–4 / 5–7 / ≥7 上**现有**语义色：位置和颜色是同一个量的两个通道（相邻档 1.06:1 的实测就是要第二通道的理由）。

**改它能让读者多知道什么**：一眼横扫就知道每只票离 50 日线多远（不用逐个读数字、也不用记颜色），线下方的票自己让出主视线，而「没测出来」第一次有了自己的样子 —— 不再被当成一只在均线下方的票。
