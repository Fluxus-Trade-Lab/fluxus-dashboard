起因：`project_liquid_leaders_tml` 的 how-to-apply 原话——「TML 多出来的那个维度（主题态）**只能前瞻判**，
`leaders_log.csv` 攒 4–6 周后回来验」。种子 2026-08-14，**今天是第 13 个 session**（不到 3 周，见 §5 的诚实话）。

## 0. 动手前先量清楚的一件事：TML 不是一个维度，是两个

`leaders_log.csv` 2,068 行的交叉表（**这是数据，不是设计**）：

| group_state | tml=True | tml=False |
|---|---|---|
| Leading | **433** | 126 |
| Weakening | 0 | 1,282 |
| Improving | 0 | 132 |
| Lagging | 0 | 88 |
| （空） | 0 | 7 |

`TML ≡ liquid_leader ∧ group_state=Leading ∧ rs_1m≥80`。所以**「TML vs 非 TML」这个对比里
78% 的对照组是 Weakening**——它同时在量「主题态」和「rs_1m 闸」两件事，
量出任何差都分不清是哪一个。⚠️ 这正是 `pitfall_same_quantity_three_names` /
`pitfall_fixing_the_reference_makes_it_an_identity` 的形状：先拆开再测。

**所以本轮测三个分开的问题，不测「TML vs 非 TML」这个混合体：**

- **H1（主题态，主问题）**：同一只流动性领头股，在它的主题处于 **Leading** 的日子买，
  前瞻收益是否高于它自己在 **Weakening** 日子买。
- **H2（rs_1m 闸）**：**只在 Leading 行内部**，`rs_1m≥80`（=TML）与 `rs_1m<80` 的前瞻收益差。
- **H3（混合体，只为可对照）**：TML vs 全部非 TML —— 报出来只是为了让它和 H1/H2 并排，
  **它是被两个维度污染的量，不作为结论。**

## 1. 度量与交易框（提前钉死）

- 收益 = `close(d+N) / close(d) − 1`，`close(d)` 取 `leaders_log.csv` 自己那一列，
  `close(d+N)` 取 yfinance `auto_adjust=True` 日线（分红拆股已调整）。
- **超额收益 = 个股收益 − SPY 同窗收益**（主报超额；原始收益一并列出）。
- **N = 5 个 session 为主**（可用日期最多且窗口完整）；N = 3 为次；**N = 10 只有 3 个 as_of，
  标为探索、不作结论**。
- ⛔ **2026-09-02 的日线不用** —— 写这份预注册时 ET 15:32、盘中，那根 K 线未收。
  数据一律截到 **last completed session 2026-09-01**。

## 2. 样本与 holdout

- 样本 = `leaders_log.csv` 全部 13 个 as_of（2026-08-14 → 2026-09-01）。
- **本轮不划 holdout，因为划不出来**：13 个 session、一个市况、窗口互相重叠。
  按协议这条结论最高只能到 **`candidate`**，H1 若为负则是 **`null`**（负向结论不受赢家诅咒）。
  **本轮结论一律不得进入任何代码闸门、席位规则或面板文案。**
- 前瞻账本继续攒；真正的 holdout = 09 月之后的新 as_of，**那时才跑第二次，且只跑一次**。

## 3. 检验设计（先说清楚为什么这么设计）

主检验 = **按 ticker 配对的 Wilcoxon 符号秩**。
每只票算两个均值：它自己 Leading 日的平均超额、它自己 Weakening 日的平均超额，取差。
两者都有的票才入样（预计约 100 只）。

为什么是配对：①票的质地被自己吸收掉（不再是「好票更容易 Leading」的同义反复）；
②差分一阶抵掉当日大盘共同项；③每票一票，**重叠窗口不会把 n 吹起来**
（`pitfall_compute_the_minimum_possible_p_first` 的教训：2,068 行的 p 值是假的）。

辅助：非配对的票级 Mann-Whitney（始终 TML 的 16 只 vs 从不 TML 的 164 只）——**一侧只有 16，
预期读不出东西，报出来是为了让「读不出」这件事有个数**。

## 4. 两个对照（没有它们，阴性不算数）

- **阴性对照**：把标签在日期内随机重排 1,000 次，主检验的 p 应近似均匀、
  |效应| 分布覆盖真实读数 → 说明我没量到的是真的没有。
- **阳性对照（本轮的核心数）**：往 Leading 行注射一个**已知**的固定效应
  （+0.5% / +1.0% / +2.0% 超额），重跑主检验，
  报出**这套设计在这个样本量下能以 ≥80% 概率报出阳性的最小效应**。
  → 这个数就是本轮的**分辨率地板**。若地板高于任何现实中可能的效应，
  那么 H1 的 NULL **是检验的性质、不是数据的性质**（`pitfall_a_stricter_test_can_be_blind`）。

## 5. 打算搜多大（如实累计）

预算 **spec_search_n ≤ 9** = 3 个假设 × 3 个 horizon（3/5/10）。
除此之外不再试别的归一、别的窗口、别的分层。若临时加了，报数时如实写进去。

## 6. 已知的、写在前面的弱点

1. **不到 3 周、一个市况。** 原计划 4–6 周，今天只有 13 个 session。
2. `leaders_log.csv` 的 `close` 是我们管线写的，`close(d+N)` 是 yfinance —— **两个源**。
   会抽样核对同一日的两个 close 是否一致，不一致的行报出来而不是悄悄用。
3. 每天入样的是**当天仍然是流动性领头股的票**，掉出名单的票当天就不再有行 ——
   起点没有幸存偏差（每一行都是「那天真的在名单上」），但**长期跟踪有**，所以只测固定 N 的前瞻，
   不做「持有到掉出名单」。
4. 284 只票的价格要现下载，**下载失败会偏向输家**（退市/改名）——覆盖率必须报出来，不许静默丢弃。
