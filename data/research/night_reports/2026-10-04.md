### 2 · ⭐ 同一份名单的三个读者，有一个会被空值炸——而一个专门喂空值的测试看不见它

`audit_universe_population` 是 12 个 NEVER 行里的第一个，第一次量：**55/67**。
12 个存活点里**三个挤在同两行上**——按 09-26 那条「存活点密集挤在一处先当死代码查」
去看，查出来不是死代码，是 `check()` 里**同一份市值名单有三个读者、问的不是同一个问题**：

| 读者 | 写法 | 吃空值 |
|---|---|---|
| 当天的 `caps` | `[c for c in caps if c and c > 0]` | ✅ |
| `share_small()` 的分母 | 同上 | ✅ |
| 「这个打底日有没有中位数」 | `any(c > 0 for c in by_session[p])` | ❌ `None > 0` 抛 TypeError |

**它为什么躲过了一个专门喂空值的测试**：`any()` 短路。
`test_blank_caps_are_dropped_before_anything_is_counted` 从写下来那天就在喂空值，
写的是 `list(BIG) + [None] * 50`——第一行就是 5e9，`any()` 当场返回 True，
后面那 50 个 `None` **一个都没读到**。现场实测，同一场数据只换顺序：

```
None 在最后（现有测试的写法）: ok=True  rows=20
None 在最前              : TypeError: '>' not supported between 'NoneType' and 'int'
```

⚠️ **出厂路径打不出来，所以这不是 P0**：`snapshots()` 用
`float(r.get('market_cap') or 0)` 把空值折成 0，线上喂进 `check()` 的永远没有 `None`。
真正的毛病在 `check()` 是文档明写「pure」、被直接测的公开函数，
而它自己内部对「什么叫一只有市值的票」**有两个定义**——没有测试的那个就是错的那个。

修法照 09-29 的教训：不是换字面量，是让三处**问同一个量、同一个算子**——
抽出 `positive_caps()`，三处共用（`de260c5b3`）。

`c > 0 → c >= 0` 全绿（真等价，`c and` 已挡掉 0）。
旧的 `blank_caps_are_dropped_before_anything` 在坏代码上**照旧是绿的**——这正是本条的要点。
