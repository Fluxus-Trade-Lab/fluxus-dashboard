### 甲 · Joe 那 6pp「仪器噪声」不是噪声 —— 它在拿上一个变异体的字节码测这一个

**结论先说**：`audit_mutation_sweep` 连续四晚报出的杀死率里，**有一部分判定属于错误的变异体**。
这比「噪声」严重——噪声是读数不准，这是**读的不是那个东西**。

**机制**：CPython 判一个 `.pyc` 还能不能用，只看两件事——
**源文件 mtime 取整到整秒**，和**源文件字节数**。
工具的循环是「写入变异体 N → 跑 pytest → 写回原文件 → 写入变异体 N+1 → 跑 pytest」。
相邻两个变异体都是同一模块的 `ast.unparse` 输出，**大小只差这次改动本身的长度**——
`20 -> 21`、`0 -> 1`、`== -> !=` 这个差都是 **0**。
同一秒内写完，**变异体 N+1 就是用 N 的字节码跑的，而报告上写的是 N+1 的名字。**

**为什么四晚没人看见**（这部分比 bug 本身值得记）：

| 你会做的检查 | 它给的答案 | 为什么骗人 |
|---|---|---|
| 把单个变异体隔离连跑 12 次 | **12/12 完全一致** | 隔离时「上一版」就是它自己 |
| 同一次调用里连跑 3 次（`--repeat 3`） | **49 个变异体零翻转** | 同样因为上一版没变 |
| 三次独立调用 | **41% / 45% / 47%，10 个翻转** | ← 只有这个能看见 |

也就是说：**它在所有「重复测量」式的检查下都是完美的**，只在跨调用时露馅。
这与 [[pitfall_having_a_row_is_not_having_data]] 同族——**按内容切一半的源，在所有计数维度下都完美。**

**让它现形的不是多跑几次，是问了一个别的问题**：*翻转的那些，有什么共同点？*
→ **与前一个变异体的字节差全部是 0**（实测 48 对相邻里 22 对满足这个条件）。
干预确认：关掉 pyc 缓存后连跑 3 次 —— **45% / 45% / 45%，存活集合逐位相同。**

⭐ **可迁移的一句**：**噪声不该有结构。**
一台「有 6% 随机噪声」的仪器和一台「有时在测错对象」的仪器，读数长得一模一样，
区别是**后者的错误里有规律**。看到「随机波动」先别当误差项吃掉，先问：波动的样本彼此像不像。

**修法**：pytest 子进程走 `-B` + `PYTHONDONTWRITEBYTECODE=1`。commit `deb7a0f5`。

**同批另外三件**（⚠️ 起因是本轮第一个发现：**这台专门问「你这道闸有没有阳性对照」的机器，自己四晚一条测试都没有**）：

1. **`pipeline/tests/test_audit_mutation_sweep.py` 首次建档，7 条**，其中三条是**注射式阳性对照**：
   注射一个真 flaky 的测试 → 必须报 `UNSTABLE`；注射一个 hang → 必须报 `no_verdict`；
   去掉 `-B` → 必须报出残留的 `.pyc`。**四条在旧代码上实测为红**（不是「应该会红」）。
2. **`--repeat N`**：同一变异体跑 N 次，一次绿一次红的报 **UNSTABLE 并排除出杀死率分母**——
   仪器说「我不知道」，而不是随机投一票。
3. **超时不再算「被杀」**，改记 `no_verdict`。原来把「机器忙」读成「测试抓到了」，
   而且**机器越忙这个假阳性越多**。另：`survivors` 补 `index`——`(line, kind, change)` 不唯一，
   按它对照两次运行会把 15 个存活并成 14 个（今晚实测撞上过）。

**同形状全仓扫过**：`pipeline/` 里「写文件 + 起 python 子进程」只有这一处
（`federation_board.py` 的命中是文档字符串）。**不扩散。**
