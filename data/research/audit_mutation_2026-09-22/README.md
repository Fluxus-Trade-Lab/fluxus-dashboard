### 补的是什么（`pipeline/tests/test_audit_universe_freshness.py`，16 条 → 36 条）

原来的 16 条测的是**性质**：口径是比值之和不是比值之平均、三种失败方式各一个阳性对照、
好带两端静音、时区陷阱。**和昨夜那道闸欠的是同一笔账**——边界、`main()`、读取端：

1. **每条阈值正好卡在线上时的取舍**——rvol 正好 0.5（干净）vs 0.4999（F1）· 正好 3.0（干净）vs 3.0001（F2）·
   正好 200 只（是宇宙）vs 199 只（是碎片）。
   ⚠️ 钉默认阈值**不能**写 `assert HIGH == 3.0`——那是读自己那个常量，对真代码和变异体一样绿
   （09-23 那班在 pp 换算上正栽过这一下）。用的是只在正确阈值下才改判的数：`classify(3.5)` 必须是 F2，
   HIGH 一挪到 4.0 它就读成干净；而「95.4 是 F2」这种实测坏值**钉不住 HIGH**，挪到 4.0 照样红。
2. **非有限数必须贡献 0**——nan 泄进分子，整条比值变 nan，`classify` 里每一个比较都读 False，
   **这道闸会对一份坏货一声不吭**。这是 `_num` 那一行存在的全部理由，此前没有一条测试问过。
3. **最小的正分母仍然是分母**——判不了的判据是「分母 ≤ 0」，不是「分母小」。
4. **没有时区的时刻按 UTC 读，不按本机的钟**（宪法那条「不用本机 JST 钟」的代码版）。
   两个时刻各贴着 ET 那一天的两端（00:30 与 23:30），**本机时区一旦成为解释依据，
   无论它偏东偏西，这两个里至少有一个会掉到隔壁那天去**——所以这条测试不依赖跑它的那台机器在哪。
5. **一场只有一份快照、而它是坏的，同样是 F4**。`seen > 0` 写成 `seen > 1`，
   单快照的场次会从 F4 里整个漏掉——而「一天只提交过一份」正是最容易漏的那种日子。
6. **人读的那几句话**——违规行要点名是哪个 sha（早上八点读它的人要能直接 `git show`）·
   F4 那行数的是它真看见的快照数 · 同一场里多份快照按 sha 排而不按调用者递进来的顺序
   （否则同一份历史换个读取顺序就给出另一张报告）· 缺 `names` 字段记 0 不记 1。
7. **`main()` 的三个退出码**——此前一行没测过。`2` = 一份快照都没查到（**0 个违规和 0 次检查长得一样**）·
   `0` = 干净 · `1` = 有违规；外加 `-q` 到底丢什么（丢干净行和 F3 警告，**永不丢出事那一行**）、
   判不了的 rvol 印 `-` 而不是崩。
8. **`snapshots()` 的读取契约**——此前完全没测过：空文件不是空宇宙 · 半截 JSON 跳过 ·
   没有时间戳不猜日期 · 缺 `rows` 记 0 只而不是崩 · 短 sha 八位 · 旧的在前 ·
   路径从没被提交过时返回空（一路传到退出码 2）。
   这里住着两处 `capture_output/text`：**它一旦拿回 bytes，`git show` 会拿着 `b'...'` 去查、
   一份货都读不到，而这道闸的结论会变成「没有违规」。**

### 补的是什么（`pipeline/tests/test_audit_unpushed.py`，8 条 → 19 条）

**同一笔账，第三次**：性质测过了（U1/U2/U3/U4 各有一个阳性对照），
欠的是**读取端的失败态**和 **`main()`**。

1. **git 一句话都答不上来的时候**——一个不是仓库的目录，计数必须是 0 而不是 1。
   docstring 写着「a broken worktree must not kill the sweep」，但**不杀死不等于读成有罪**；
   `else 0` 一旦变成 `else 1`，这道闸会对着一个坏掉的目录喊「这里有 1 个 commit 要没了」。
2. **路径里有空格的 worktree**——`worktree list --porcelain` 每行是 `worktree <路径>`，
   maxsplit 从 1 变成 2，它就去查 `/tmp/a` 而不是 `/tmp/a b/wt`，
   然后把**一棵活的、装着未推工作的树**报成 U4「目录没了」。
   （本班自己就跑在 `/var/folders/.../fx-worker-wt-*/wt` 这种路径下。）
3. **U1 和 U2 是互斥的**——U2 的定义是「这些 commit 在别的远端 ref 上」，
   U1 的 commit 哪儿都不在；同一批工作不能既是 U1 又是 U2。
   干净的跟踪分支同理：`a and not n` 写成 `a or not n`，它会给一棵干净的树挂上「领先 0 个 commit」。
4. **U3 只数已跟踪的改动**——⚠️ 原来那条用 1 个已跟踪改动 + 1 个未跟踪文件，
   **两种写法都数出 1**，它对这个判据本来就是瞎的。改成未跟踪的比已跟踪的多，两个数才分得开。
   这正是 09-23 那班在 pp 换算上栽的同一种：**一条对真代码和变异体一样绿的测试。**
5. **tracking 指向一个已被删掉的远端分支**（真会发生）——读出来是「没配 tracking」的警告，
   不是「有活要没了」的违规。
6. **`main()` 的两个退出码与那一行人读的字**——此前一行没测过：
   `OK `/`BAD` 这个旗、分支名、没事时印的 `clean`、末行的汇总句、`--json` 报告里点名是哪棵树。
