# Gate 声明制 + 封顶三行制 · 9 个定时任务书审计

**做的人**：Plumber Joe（08-28 晨检认领 INBOX 2026-08-27 OPS 挂单）
**出处**：Andy 交办的 @polydao loop engineering 五件套（Trigger/Work/State/Stop/**Gate**）
**判据（原文口径，不放宽）**：gate 必须是 **agent 控制不了的东西**——① 会失败的检查 ② 对不上的计数 ③ 没见过原稿的第二个上下文。
**agent 自审必然自我批准，所以「我会仔细检查」不算 gate，「铁律：不许 X」也不算 gate**——那是 Work 里的指令，不是 Stop 前的闸。
**封顶三行** = ① 量上限 ② 输入不正常时怎么办 ③ 降级路径。

---

## 一、结论（一句话）

**7 个在跑的任务里，只有 2 个（zac-night-study、joe-morning-check）有第③类真闸；4 个封顶三行不全；`fable-ceo-brief` 与 `ops-console-refresh` 是零真闸——而这两个恰好是 Andy 每天唯一看的两样东西。**

零真闸不是理论风险，已有实证：Zac 08-28 测出联邦看板 lane 归属 **38.5%**、首页「等你拍板」是**假零**，而 `ops-console-refresh` 每天照常 republish 了它 —— 因为该任务书唯一的闸是「脚本报错就停手」，只挡崩溃，不挡内容错。

## 三、补法（最便宜的一种，逐个给 `update_scheduled_task` 补丁文本）

> ⚠️ **本轮只出补丁不落**。改别人线的任务书是持久化配置写入，且 §五 分级修复的白名单不含 `~/.claude/scheduled-tasks/`——按「拿不准归哪级就按②办」，补丁挂给对应线的主人。我自己那条（#2）也一并挂着，等 Andy 一次点头再统一落。

### #6 `fable-ceo-brief` —— 加「数字出处」尾节，闸是 Joe 次日抽查

在「## 约束」节追加：

```
- **数字出处（Gate，Andy 08-28 定）**：早报正文之外附一节 `<details>数字出处</details>`，
  每个业务数一行 `<数> ← git show origin/main:<权威源路径>`，是现场读到的原文不是复述。
  Joe 次日 07:20 晨检**随机抽一条核对**，对不上写进 §七 并在 todo_cron_check 记一次「早报数字错」。
  连续两次不符 = 停用数字段，只报动作不报数。
- **降级路径**：7 个采集源中任一读不到 → 该段写「<源名> 今天读不到」，**不拿昨天的数顶替**；
  三个以上读不到 → 只发【今日三件】一段，标「反馈段缺席」。
```

**为什么这是真闸**：Joe 是第二个上下文、没见过早报草稿、抽查会失败并留痕。fable 自己控制不了 Joe 抽哪一条。

### #7 `ops-console-refresh` —— 两条不变量断言写进脚本，不过就拒绝 publish

第 4 步前插入新的一步：

```
3.5. **发布前闸（Gate，08-28 定）**——断言不过就**不 publish**，只汇报：
   a. **假零守卫**：`等你拍板` 为 0 时，必须同时打印三个数据源（§七/§12 未勾行、增长台账 `status: 待办`、
      INBOX「给 Andy 的待办」）各自的计数，三者皆 0 才允许发 0；任一非 0 而看板是 0 = 拒发，报「假零」。
      （Zac 08-28 已做过阳性对照：撤掉数据源后该守卫精确报红。）
   b. **树龄守卫**：`git rev-parse HEAD` 必须等于 `git rev-parse origin/main`；不等就拒发，
      报「脚本树落后 origin/main N 个 commit」。（08-28 实测主树落后 411 个。）
   两条断言在脚本里，agent 改不了也绕不过——这是本任务唯一的 gate。
```

外加第 2 步的路径改成基于 `origin/main` 的临时树（Zac 08-28 §四② 已提，同一个病根）。
