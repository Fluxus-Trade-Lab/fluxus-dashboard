# 「待合分支」这句话，三晚都没人能核

**2026-09-07 夜间组** · 工具 [`pipeline/tools/audit_stranded.py`](../../../pipeline/tools/audit_stranded.py) · 测试 [`test_audit_stranded.py`](../../../pipeline/tests/test_audit_stranded.py)

---

## 一、起因

09-05、09-06 两份晨报都写着同一句：**「待合分支 `fbclock` · 建议合 y」**。09-07 第三晚，它还在。
上一班留的话是：第三晚仍未合，就不再是「等人合」，是三次律的第 3 次。

于是本轮不写第三遍，改去查一件事：**这句话是怎么算出来的，它算得对吗。**

## 二、五把尺子，五个答案

同样七条分支，同一时刻，五种量法：

| 量法 | 它其实在回答什么 | 09-03 那条的读数 |
|---|---|---|
| `rev-list --count main..B` | 领先几个 commit | 9 —— 听起来欠着一整晚的活 |
| `diff --stat main...B`（三点） | 从分叉点起分支加了什么 | 1228 行（记忆在案：885 文件的假警报同款） |
| `diff --stat main B`（两点） | 两棵树的差 | 被「落后 321 个 commit」淹没，读不出 |
| `git cherry main B` | patch-id 有没有重复 | 9 个 `+`，判「全都没送到」 |
| `merge-tree --write-tree` | 并进去会怎样 | **冲突**，不给答案 |

真相是：**这条分支的内容早已全部在 main 上**，1228 行里只有 3 行不在，而那 3 行是晨报骨架的
占位符（「*（进行中）*」），后来被正文替换掉了。

五把尺子里没有一把回答了人想问的那个问题。

## 三、换一个判据：行

```
base = merge-base(main, branch)
分支相对 base 加的每一行 → 能不能在 main 的同名文件里找到
```

不对称是故意的。三个 append-only 公箱（INBOX / material_inbox / DATA_CONTRACTS §七）最爱滞留，
而 main 上恰恰是「我的行 + 别人的行」。要求相等，公箱永远判「没送到」；
问包含，才是人真正在意的关系——**我那行在不在 main 上。**

## 四、第一个坑：报绿的检查，其实什么都没看

第一版跑在 zsh 里：

```sh
files=$(git log main..B --name-only --format='')
for f in $files; do git diff --quiet main B -- "$f" && ...
```

zsh 不对未加引号的展开做分词。`$files` 变成**一个**用换行拼起来的 pathspec，匹配不到任何文件，
`git diff --quiet` 于是返回 0——「无差异」。五条分支全部打上 ✅ 已送到。

**匹配不到文件的 pathspec，和干净的 diff，长得一模一样**，而失败的方向指向绿色。

这条已经写进工具：`added_lines()` 遇到两侧都不存在的 blob 就抛错，不返回「没有变化」。
测试 T1/T1b 各钉一半——一半钉我们抛错，一半钉 git 确实会那样返回 0（git 哪天改了，理由要重写）。

## 五、第二个坑：方向反了，而它更贵

`fix/alex-stockbee-s2-prev-volume` 有 8 行测试代码不在 main 上。第一反应是「生产代码合了，
守它的测试没合」——听起来正是 [[pitfall_tested_the_module_not_the_wiring]] 的倒影。

读 diff 才发现方向反了。**main 上是更好的那版。**

- 分支版：读 `run_all.py` 的源码文本，grep `'prev_volume'` 在不在 `universe_cols` 里。
- main 版（09-05 换的）：真跑一遍 enrichment，断言列出现在出来的 frame 上。
  它的 docstring 写着为什么换：*那个测试有几周一直是绿的，而那一列当时并不存在——
  清单上写了名字，把 helper 的键变成列的那行只搬了四个里的三个，`export_cols` 悄悄丢掉缺的列。*

**按「建议合」把这条合进去，是回退。** 一把看起来在报绿的尺子，会推荐一次回退。

所以「不在 main 上」只有在 **main 自分叉后没碰过那个文件** 时才等于「滞留」。
工具逐文件算 `git log base..main -- <file>`，碰过的一律判 🟡 **过期**，永不写「建议合」。

## 五点五、两个坑是同一个形状

一个把「没看」读成「干净」，一个把「被换掉」读成「缺失」。
共同点：**尺子回答的问题，比报告上那句话窄**，而窄掉的那部分，正好是判断要用的那部分。

## 七、结论

`fbclock` 那句「建议合 y」**三晚都是对的**——本轮用一把新尺子独立复验，它是唯一一条真滞留的。
但同一份晨报上其余六条「待合」里，有一条合进去会回退，两条根本已经合完了。

**这句话对了一次，是碰上的，不是算出来的。** 三次律要升的机制不是「催人合分支」，
是**让这句话可核**：`audit_stranded` 现在能算出「真滞留 / 过期 / 已送到」三态，
接进出晨报那一节，「建议合 y」才是一个读数而不是一句印象。

## 八、这把尺子看不见什么（先说清楚）

- **行搬了家**：一行原样挪进另一个文件，它会判「缺」。本轮 6 条 🟡 里有多少是这种，没单独量。
- **同名不同意**：一行文本在 main 上存在但语义不同（比如同样一句注释挂在别的函数下），判「已送到」——
  会漏报。所以它给的是**下界**，不是精确值。
- **只看加的行**：分支删掉的行有没有在 main 上也删掉，不查。
- 09-02 的坑同样适用：这三态是**读数**，不是许可。真要合，人还得读一遍 diff。
