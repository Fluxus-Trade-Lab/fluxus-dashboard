# 研究协议 —— 什么算「测过了」（2026-08-23 立）

**为什么有这份文件**：08-23 紧凑度研究把 32 次比较里的最大值（48.3% vs 28.7%）当晚写进了
main 和契约，样本外检验是 Andy 追问一个活读数之后才补的——结果只复制到一半（+11.8pp，
p=0.047，按搜索次数校正后不显著）。同日另有三个计算错误进过书面结论。Andy 的裁定：
**「是建立机制，熟悉什么是完整的合理的测试环境，什么是专业的测试机制。」**
这份文件就是那个机制。它不靠自觉，靠 §五 的台账和 CI 闸门执行。

## 一、结论的生命周期（状态阶梯）

每一条量化结论（"X 有优势 / X 无优势 / X 预测 Y"）都处在且只处在一个状态上：

```
preregistered → candidate → validated → live
                    ↘ null      ↘ retracted
```

| 状态 | 含义 | 允许出现在哪 |
|---|---|---|
| `preregistered` | 假设已封存（见 §二），还没算 | 研究目录 |
| `candidate` | 样本内成立，**没过 holdout** | 研究报告；代码里可以算字段，**不许当阈值/闸门/席位规则，不许在面板文案里当事实** |
| `validated` | 过了 holdout（独立票池或独立时段，一次性） | 可进代码当规则；引用时必须带 holdout 数字 |
| `live` | validated 之后有前瞻账本在逐夜记录（shadow tracker） | 同上，且引用时给账本路径 |
| `null` | 测过、无优势 | 到处引用都行——负向结论不受赢家诅咒影响，是本仓库最可靠的产出 |
| `retracted` | 曾经声明过、后来撤回 | 只出现在台账里，带撤回原因 |

**铁律 1**：`candidate` 永远不能变成任何会改变 Andy 每天看到的名字的东西。
**铁律 2**：状态只能由证据推动升级，不能由措辞推动（把「有优势」改写成「似乎有优势」不改变状态）。

## 二、动工之前（预注册）

任何新因子/新假设，**在跑第一行计算之前**，先写一个预注册块并 commit（模板
`docs/templates/study_prereg.md`，Selection Lab 的封存预测就是这个模式的先例）：

1. **假设**：一句话，可证伪。
2. **度量与交易框**：赢/输怎么定义（R 是什么、几天、什么先到算赢），提前钉死。
3. **样本与 holdout 的划分**：现在就划，写明 holdout 是什么（另一批票 / 另一段时间），
   并承诺 **holdout 只跑一次**。跑完不满意回去改参数 = holdout 已烧掉，需要新的。
4. **打算搜多大**：大概会试多少个变体。最后报数字时按实际次数报。

## 三、样本内阶段（可以自由搜，但要记账）

- 随便搜。但 **spec_search_n 要如实累计**：试过的每个量、每种归一、每个阈值、每个具名变体都算一次。
- 报任何正向数字时，必须同句带上「这是 N 次比较里的最大值」。
- **完整测试环境检查单**（每个研究至少过一遍，垮过的打 ⚠）：
  - ⚠ **前视**：排名/百分位是否用了未来数据（08-23 within-ticker 第一版全期排名有前视，改扩张排名后 22.9→13.3）
  - ⚠ **重叠样本**：相邻信号日高度相关，n 虚高（28,676 行的 p 值全是虚的；去重叠后 3,706）
  - ⚠ **样本选择**：票池怎么来的决定结论（event_bars 自带幸存偏差；[[pitfall-the-universe-chose-the-answer]]：换池后 t=−2.29 变 +0.34）
  - ⚠ **状态混叠**：一个数字混两种状态（atr_pctl 低 = 真压缩 or ATR没追上价格，两种表现相反）
  - ⚠ **空列/NaN 假象**：任何「全 0 / 全同值」的列先当 bug 查（口袋支点空列报出 +10.7pp 假分辨力）
  - **阈值 vs 梯度**：惯例阈值（<20）在条件分布下可能切在没人处；先看五分位单调性再谈阈值
  - **市况分层**：至少按季度/regime 切一刀（2026Q2 普涨季分辨力 +1.6 ≈ 0）
  - **对照组**：正向结论要有一个「理应无效的对照」同框跑（绝对值、乱序、SPY 自身）
  - **确定性**：固定 seed；样本文件记 hash 或生成命令，报告可复跑

## 四、holdout 与升级

- holdout = 预注册时划好的那份，**跑一次**。
- 通过标准：方向相同 + 幅度不低于样本内的一半 + 按 spec_search_n 校正后仍显著
  （Bonferroni 即可：p_holdout < 0.05/1——holdout 只测一个赢家，所以是单次检验；
  真正要校正的是**样本内**声称的显著性）。
- 没过 = 留在 `candidate` 或转 `null`，照实写。**「方向对但幅度掉一半」是赢家诅咒的正常形状，不是接近成功。**
- `validated` 想升 `live`：建 shadow 账本逐夜记（momentum97_shadow / leaders_log 的模式），4–6 周后看前瞻样本。

## 五、台账与闸门（机制的牙齿）

- **台账**：`data/research/claims/claims.jsonl`，一行一条结论（schema 见
  `pipeline/tools/claim_registry.py` 文件头）。新结论**当天登记**，改状态改台账。
- **闸的依据分三类**（`gate_basis`）：`claim`（默认——研究结论自身撑闸，R4 要求 validated/live/null）、
  `owner-decision`（Andy 拍板——决策权不需要 holdout，但必须引「谁/何时」）、
  `third-party-definition`（公开定义的工具——EP/LL-HL 这类面板的存在不依赖 edge 主张）。
  后两类免 R4 但**结论自身的状态照常诚实记**：决策归决策、科学归科学，台账两个都记。
- **闸门**：`python -m pipeline.tools.claim_registry --check` 在每日 CI 里跑，违规即红：
  - schema 违规 / id 重复
  - 正向结论缺 `spec_search_n`
  - `validated`/`live` 缺 holdout 证据块
  - `gates` 非空（= 这条结论在代码里当了规则）但状态不是 `validated`/`live`/`null`
- **回填**：08-23 起两个盘点 agent 的产出逐条入台账；在此之前的正向结论一律先记
  `candidate`，除非能指出它的外部对照或 holdout。

## 六、证据的可靠性分级（引用任何旧结论前先对号）

| 级 | 类型 | 例 | 默认信任 |
|---|---|---|---|
| A | 外部真值复现 | oratnek RS 1M 29/29、Momentum 97 累计 98/105、Pine 黄金对照 | 高——判据不在我手里 |
| B | 抓到过真 bug 的检查机制 | audit I1–I7、run_all smoke（首跑抓 3 bug）、staleness（抓到 47.1% 冻结） | 高——用工作成果自证 |
| C | NULL / 负向结论 | RMV、VCS、h_score、52wh 动量、sequence mining | 中高——不受赢家诅咒影响，但可能是功效不足的假阴性 |
| D | 自家回测的正向结论 | 3WT +1.11、COIL 崩盘期、EP precision、Euphoria V 型反弹 | **低——默认当噪声**，直到 holdout 说话 |

- **到期规则**：回填没完成也不摘闸门——闸门先行，台账逐步补齐
