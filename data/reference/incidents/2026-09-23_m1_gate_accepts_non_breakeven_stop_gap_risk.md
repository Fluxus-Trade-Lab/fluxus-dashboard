# 2026-09-23 · M1 钱闸对非保本止损被跳空穿透，裁定接受为已知残余风险（未发生，非事故复盘）

**发现人**：T-0923-58 复核（第二轮）在真实 09-22 book 里找到 · **裁定人**：T-0923-70（ops）

接受决定，按 incident-report 的格式落档，是为了让半年后重新踩到同一形状的会话能在这个目录里

## 一、形状

`pipeline/content/recap/visual._book_money_gate`（M1）用「止损（R）是否高于当前浮盈（R）」这条
关系闸，抓价格字段被误接进 R 列的泄漏（`stop_price=142.50` 混进 `stop_R` 列会立刻大于任何合理的
`open_R`）。T-0923-61（已合 main `bc4debc4`）给「止损已上移到保本位（`stop_R==0`）」的仓位开了
无条件豁免——依据是「真实股价永远不会恰好是 $0.00」，这是一个跟数值无关的硬事实判据，可以无条件
放行而不削弱抓漏能力。

复核时在同一份 09-22 book 里发现**同族但没被覆盖**的两个仓位：**PLTR**（`stop_R=-1.0`，止损已上移
到锁定部分亏损的位置，但不是 0）、**SOXL**（`stop_R=-0.03`，同类，更接近 0 但仍非零）。这两个止损
不是「保本」，`stop_R==0` 的豁免逻辑套不上，闸对它们仍然生效——如果 `open_R` 跳空跌破这个非零止损
位（如 PLTR 跌破 -1.0R），`_book_money_gate` 会 `raise SystemExit`，炸掉整份 PDF。

## 二、根因

`stop_R==0` 能被无条件豁免，是因为「$0.00 从不是真实股价」这条判据**跟数值大小无关**，是一个硬
事实。非零止损（-1.0、-0.03……）在数值上**没有这种硬区分**——没有一个判据能保证「-1.0」或「-0.03」
不可能碰巧是被误接的价格字段本身（虽然真实股价几乎不会恰好落在个位数量级的小数上，但判断「这个
数字看起来像不像价格」已经是量级判断）。M1 的 docstring 明确拒绝做这类判断：
`"The check is not 'is this number too big', which is a judgement the ladder cannot make."`
所以把非零止损也无条件豁免，等于重新打开这个 M1 明确关闭的判断维度——这不是 T-0923-61 那次「保本
止损」范围明确的修复能顺手带过的事，需要单独评估。

## 三、影响范围（估算，未实测触发）

- **已确认存在的仓位形状**（09-22 book 实例）：PLTR `stop_R=-1.0`、SOXL `stop_R=-0.03`。
- **触发条件**：该仓位的 `open_R` 单日跳空跌破对应的 `stop_R`。
- **概率判断（未量化，凭仓位结构推理）**：非保本止损离当前价通常比保本止损远——保本止损几乎必然
  在价格回到入场价附近的常规行情里就会被触碰并结算掉那笔仓位（届时 `stop_R` 字段随之改变或仓位
  关闭，不再挂在 book 里等着被跳空穿透）；非保本止损要被跳空穿透，需要更大幅度的单日跳空。
  这是选择「暂不处理」的主要依据，但**没有拿历史跳空数据实测验证过**，是一个待补的缺口。

## 六、教训

1. **能无条件豁免的判据，必须是跟数值大小无关的硬事实**（$0.00 不是价格），不是「这个数字看起来
   离谱」——后者是量级判断，M1 的设计哲学明确拒绝做。
2. **复核找出的残余风险不等于必须当场修完**——范围明确的修复（T-0923-61 的保本止损）和需要重新
   评估设计哲学的修复（本记录的非零止损）是两类工作，硬凑进同一个 commit 会让复核员或下一个读者
   分不清「已解决」和「已知晾着」的边界。
3. **概率论证不是实测**——本记录的「非保本止损离价更远，概率更低」是推理，不是拿历史数据量出来
   的数字；下次如果有空，应该拿 `data/history/` 里的跳空幅度分布实际算一下这条论证站不站得住。
