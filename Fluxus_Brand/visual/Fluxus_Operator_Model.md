# 操作者模型 — 视觉改版的设计简报

*来源:2026-07-31 复盘(Discord)被会员用 ChatGPT 反向拆解,原始 PDF `~/Downloads/fluxus_market_operator_analysis.pdf`。*
*用途:视觉改版的一号简报。它定义**要把什么外化**,不定义长什么样。*

---

## 〇、这份文件为什么存在

改版的核心命题不是"不好看",是:

> **数据太多,我知道看什么,但别人无法像我一样处理讯息,得出结论。**

复盘里写的是事实,推理在脑子里。第三方把推理拆出来之后,它显示出一个**极其规整的结构** ——
规整到可以直接当界面骨架用。下面六个对象就是那个骨架。

判据一句话:**设计的任务是让推理被看懂,不是让数字被看见。**

---

## 一、四个语域(Fact / Interpretation / Anticipation / Action)

拆解的第一个发现:复盘的绝大部分是**事实观察**,真正的预测极少。

| 语域 | 例 |
|---|---|
| **Fact** | SPY +0.7% 收回 21d+50d;RSP −0.17%;30Y 破 2007 高 |
| **Interpretation** | "possible bottoming";"Mag 7 carrying";"broad AI 仍需修复" |
| **Anticipation** | 等 FTD |
| **Action** | `Mode: waiting for FTD` |

**设计含义:** 这四层必须有**可见的字体层级差**。读者要能一眼分出"这是测量"和"这是他的读法"。
这同时是品牌资产 —— 在一个把观点当事实卖的行业里,把测量和判断分开印,本身就是立场。

---

## 二、状态板(十维)—— 最重要的一个对象

周五收盘时他脑子里的板子:

```
Damage              substantial
Selling pressure    possibly exhausted
Index repair        started
Leadership repair   started
Mega-cap leadership good
Broad AI            poor / early
Breadth             poor
Rates               dangerous
Confirmation        absent
Risk posture        wait
```

**这才是真正的判决横幅。** 现在仪表盘顶部是三个标签(Risk / Exposure / Trend),它给结论不给成分。
十维状态板给的是**结论的构成** —— 陌生人扫一眼就看见"五项在修,四项没跟上,确认缺席 → 所以等",
推理从形状里读出来,不需要相信任何人。

**设计含义:** 顶层对象从"标签"换成"状态向量"。每一维要能点开落到它的证据。

---

## 三、修复的阶梯(cross-sectional ladder)

他给个股排的不是涨跌,是**修复进度的梯级**:

```
broken → 止跌 → undercut/reclaim → 收回均线 → pivot → breakout → breakout 站住 → expansion
```

7/31 的位置:AMZN 最靠前;MSFT/NVDA 次之;ANET 在测试位;广义 AI 名字远远落后(在 declining 50d 上 gap-and-fail)。

**未来几天他真正在问的:更多股票有没有往上爬这个阶梯?** 这比"SPY 明天涨不涨"重要得多。

**设计含义:** 筛选器现在是**列表**,应该是**阶梯**。名字按梯级落位,"领涨扩散"就变成肉眼可见的**质量上移**。
把多天叠起来看,它自然是一张密集的场图 —— 这一点很关键,见 §七。

---

## 四、传导链(propagation chain)

他的问题不是"市场会不会涨",是"**这个修复能不能传导出去**":

```
AMZN / MSFT / NVDA → 更多 AI 领涨 → QQQ 收回 → breadth 扩张 → RSP / IWM → breakout 站得住
```

每一环有"亮 / 没亮"两态。7/31 只亮了第一环。

**设计含义:** 这是一张**指引图**(wayfinding),不是图表。哪一环亮着、卡在哪、下一环是什么 —— 一眼可读。
这个对象跟金融视觉毫无关系,反而像交通/工业标识系统。Otl Aicher 那条线在这里落地。

---

## 五、序列,不是快照

> 他的信息单位不是快照,是**序列**。

```
周三 liquidation → 周四 止跌+反弹 → 周五 延续+领涨收回 → ??? FTD → ??? breadth 扩张
                                                       ↑ 待定格
```

**待定格**是这里最重要的视觉发明:**把还没发生的事画出来,并且标明它待定。**
`Mode: waiting for FTD` 之所以只有一行,是因为前面所有观察都只为了决定"进入什么模式"。

**设计含义:** 每个指标都该显示最近 N 天的**轨迹**,而不是今天的值;并且时间轴要向右延伸到**空槽**。
这同时把 Time Machine 从"回放功能"变成"叙事装置"。

---

## 六、"working"的定义要重写

他的 working / not working 不是绿 / 红:

> **市场给了它一个证明自己的机会,它有没有接住?**

- working:catalyst/技术机会 → 需求出现 → 收回关键位 → 进展延续
- not working:拿到买盘 → 反弹 → 撞到套牢盘 → **失败**(gap-and-fail at declining 50d)

**设计含义:** 颜色不能只编码涨跌。至少要能表达**"给了机会 / 接住了没有"**这一组关系。
这直接影响 §视觉改版里"钱用绿红、市场用橙蓝"的分层决策 —— 市场那层编的不是方向,是**回应质量**。

---

## 七、乐谱与 Mehretu 在这里合流(重要)

改版一直在两个方向之间悬着:**乐谱**(指令外化)和 **Mehretu**(密集的场)。这份拆解显示它们不冲突:

- 他的七层观察顺序(① 指数结构 → ② 参与度 → ③ 领涨 → ④ 受损名单 → ⑤ 技术测试的反应 → ⑥ 宏观作为约束 → ⑦ 最后才是行动)
  **本身就是一份乐谱** —— 固定的读谱顺序,每天照着走一遍。
- 而 §三的阶梯 × 几百个名字 × 若干天叠起来,**天然是一张密集的、层积的场图**。
  那些笔触不是装饰,是"某只票在某天处在第几级"。

**结论:乐谱是读法,场是画面。同一个系统的两个面。**
Mehretu 的兴奋点因此不必牺牲信息密度 —— 密度本来就是信息。

---

## 八、给设计的六条硬约束

1. 顶层是**状态向量**(十维),不是标签。
2. **测量 / 解读 / 预期 / 行动**四个语域必须有可见的层级差。
3. 个股呈现从列表改为**阶梯**(修复进度的位置)。
4. 传导链是**指引图**,有亮 / 未亮态。
5. 所有指标显示**轨迹 + 待定空槽**,不是单点。
6. 颜色编码"**回应质量**",不只是涨跌方向。

任何视觉方案,先过这六条,再谈好不好看。

---

## 九、还没定的

- 交互的主隐喻:乐谱式 / Mehretu 式 —— §七 认为可合流,但主画面选谁没定
- 叙事式滚动:用户弱反对,未排除
- 状态板十维的**判定规则**:目前是他脑子里的,要变成可计算的阈值表(引擎已有 12 条规则,需要对齐而不是另起)
