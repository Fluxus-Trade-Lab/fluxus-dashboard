# 每日临帖 COPYBOOK — 规格

*2026-08-01 定稿。配套 `../ops/Fluxus_Content_Ops.md`(运营层)、`../ops/Fluxus_X_Playbook.md`(内容语法)、`../research/Fluxus_Fintwit_Voice_Codes.md`(形态与情绪编码)。*

> **一句话:每天把跟踪名单当日写的东西压成编号卡片,你用一行字表态,判断本身既训练你的手,也训练我的口味。**

---

## 1. 目的与成功判据

**两个目的,一个动作。** 你的每一次「存/杀」同时做两件事:给你自己积累可模仿的格式库,给我积累可校准的口味判据。

**可证伪的成功判据(4 周后回看):**

| 指标 | 目标 | 基线 |
|---|---|---|
| 我的预测命中率 | **≥ 60%**(3 猜中 2) | 随机从 25 张挑 3 张、你存 4 张 → 期望命中 ≈ **16%** |
| Swipe File 每周新增带格式码的样本 | ≥ 3 条 | 现在靠手工偶发 |
| 你的每日耗时 | **≤ 5 分钟** | Content_Ops 的每日预算是 15 分钟,这个占三分之一 |

**任何一条连续两周不达标,就改设计或停掉。** 这个机制不许变成第二个要维护的东西。

## 2. 触发与流程

**触发:** 你在会话里说「今天的临帖」。

> ### 🚨 第 0 步(2026-08-07 加,因为犯过):**先查真实日期,不从对话推断**
>
> ```bash
> python3 -c "import pipeline.marketcal as m; t=m.market_today(); print(t, t.strftime('%A'))"
> ```
>
> **每次临帖开始前必须跑这一句。** 不许从「上次对话说了什么」推今天是几号。
>
> **犯过的实例:** 2026-08-02 会话中途系统提示过一次日期,之后连续 5 天的对话里我一直以那天为「今天」,导致「周六休市」「周日批量补 bookmarks」「周一开盘前跑第二份」整条计划链建立在假日期上,**8/3 周一那份临帖的窗口就这么错过了**。
>
> **根因不是不知道日期,是把「对话上相邻」当成了「时间上连续」。** 会话可以跨天甚至跨周,两条消息之间可能过了 5 天。
> 记忆里本来就有规则「交易日期一律走 `pipeline.marketcal`,不用本机 JST 时钟」—— 有规则没用,所以现在把它钉进流程的第 0 步。

抓 X 必须由我驱动登录态 Chrome,GitHub Actions 跑不了,所以这是**会话动作,不是定时推送**。不接进 `scripts/content_reminder.py`。

```
1. 我读 list 时间线,滚 4–6 屏                      (我,约 5–8 次浏览器批量调用)
2. 我压成约 25 张编号卡片(上限 30)+ 末尾一行我的预测  (我)
3. 你回一行:「存 3 7 12 / 杀 5 9」                  (你,≤5 分钟)
4. 我落两个台账,并把误判写成一条判据               (我)
```

**跳过无成本。** 和蹭号同一条规矩:哪天不想做就不做,不算欠账,不补。

## 4. 卡片格式

每张 ≤ 3 行,固定结构:

```
#07 [师·Serenity] Did Citadel really just liquidate Situational Awareness… Then brought up entire
    markets the next day? $NBIS +26.25% $IREN +25.96% $SHAZ +22.82% $SNDK +23.98%…
    550K · 1.7K♥ · 102💬 · 形态2 数据列表 · E7
```

**角色前缀:** `师` 老师 · `蹭` 蹭号目标 · `靶` 反面靶子 · `标` 标杆(citrini 这类语感基准)
**形态码:** 见 `../research/Fluxus_Fintwit_Voice_Codes.md` §五 的九种形态
**情绪码:** 见同文件 §一的 E1–E7

**形态 vs 文体:** 卡片上标的是**形态 1–9**(描述性,覆盖所有帖子,包括平庸的和坏的)。只有被你「存」下来的样本才在入库时获得**文体 A–H**(`../voice/Fluxus_Swipe_File.md` 的既有分类)。形态是我给每条帖贴的标签;文体是你录取之后它才配拿的编号。**不新建第三套分类法。**

原文截断到约 140 字,截断处用 `…`。**不改写、不翻译、不加我的评语** —— 卡片阶段我的判断只体现在「选了哪 25 条」和末尾的预测里。

`靶` 类卡片正文只留一行,视觉上明显更短 —— 你扫过去确认「这就是坏的」即可,不必细读。

## 5. 表态语法

一行,宽松解析:

```
存 3 7 12 / 杀 5 9
```

- **只写 `存` 也行**,其余默认「过」。`杀` 必须显式写 —— 因为「过」和「杀」是两种不同的信号:过 = 平庸不值得记,杀 = 主动否决,要进反面台账。
  **值得多花那几秒:「杀」比「存」信息量更大。** 你存的东西我大概率也觉得好(我们口味重叠的部分),你杀的东西才暴露我们的分歧在哪 —— 那才是我要学的。
- **可选加一句理由**,附在编号后:`5杀:说完就停` —— 理由是最高价值的信号,但不强制。
- 不用 emoji 反应 —— 我读不到 X/Discord 的 emoji reaction,必须是文字。

## 6. 预测对照(这个机制的核心)

**每天卡片列表末尾,我先写死我的预测:**

```
— 我的预测:今天你会存 #03 #11 #19 —
```

你表态后,我在台账里记命中率,**并且把每一次误判写成一条具体判据**。

例:
> `#19 我预测会存,你杀了。理由「说完就停」→ 命中 §8.5 收藏闸:立场只拿赞,条件/清单才被存。`
> `修正:格言类卡片若不附带条件或分支,预测时降权。`

**没有这一环,「训练我的口味」就是不可验证的空话** —— 我会每天输出我已有的判断,读得再多也不变。有了它,误判是唯一真正的学习信号。

## 9. 周回顾(接在周日 prep-day 后,≤10 分钟)

每周日,我出一份:

1. **命中率走势**(周内每天一个点)
2. **本周「存」的形态分布** —— 哪几种格式你反复认,那就是你正在长出来的手
3. **从「杀」的理由里提炼的新判据** —— 是否够格加进 `../ops/Fluxus_Content_Ops.md` §8.5 的闸
4. **名单自然选择** —— 列出**连续两周零「存」**的成员。你确认后从 list 移出。

> **名单由你的判断筛,不由我的偏好筛。** 你留下谁,本身就是一条口味信号。

## 10. 边界(明确不做)

- **不自动发推。** 这个机制只产出输入,不产出输出。
- **不替你写第一稿** —— 除非你在某张卡片上点名「这条写一版」。那时走 §8.5 的七道闸,宽写 ≥10 条,只交 2–3 条幸存者。
- **靶子内容永不进 Swipe File。**
- **只抓公开数据。不订阅任何付费产品**,所以锁在墙后的内容我们永远只知道它存在,不知道它写得好不好。
- **不改你的 list。** 加人删人是你的动作;我只提议。

## 11. 已知失败模式与处理

| 失败模式 | 处理 |
|---|---|
| list 时间线混入大量回复 | §3 的过滤规则:回复只在互动显著高于该成员日常时才收 |
| 淡日/周末产出不足 25 条 | 放宽到 48 小时窗口;仍不足就少给,并说明,**不用凑数** |
| 某个成员刷屏 | 每人每日上限 3 条,靶子 1 条 |
| 我为了提高命中率而迎合 | 预测必须在看到你表态**之前**写死在卡片里;台账留痕,事后不可改 |
| 卡片量让你腻了 | 第一周 25 人满编就是在测这个。腻了就砍到 18,判据是你的实际耗时超过 5 分钟 |
| X 改版导致抓取失效 | 如实报错,不猜测、不用旧数据充数 |
| **浏览器断连**(`Claude in Chrome is not connected`) | **最多重试 2 次,然后停下来告诉用户**,不要循环重试。私密 list 必须用登录态 Chrome —— 应用内浏览器没有 X 登录,读不了,**不存在降级方案**。让用户开 Chrome + 确认 Claude 侧边栏已登录,再重跑 |
| **会话跨了多天,日期锚失效** | 见流程第 0 步:每次开始前跑 `marketcal.market_today()`。**「上次对话是什么时候」不构成今天是几号的证据** |
